    CHANGELOG¶

    The detailed changelog. The repository root CHANGELOG.md carries the same releases as short release notes. Since 4.0.0, a model or data update ships as a data pack and is listed by its pack id; app versions are listed by version number.

    [Unreleased — web] - 2026-10-08 — DATA FILES THAT FAIL A CHECK ARE SHOWN ON SCREEN¶

    A damaged or missing data file is now named on screen, and nothing that depends on it is shown. Until now, a file that failed its size or SHA-256 check after start-up was refused, but the message went only to the browser console: - the global model quietly left that economy out of the coupled solve; - a failing trade-weights file was replaced by the build-time copy; - a country that failed to load kept showing the previous country's charts under the new name.

    Now: - a red banner at the bottom of the screen names each file that failed; - a country that fails to load shows an error panel instead of charts; - the global model refuses to load from a partial set of economies, or from fallback weights, and says so.

    A file the data pack does not list is still treated as "not shipped" (for example an economy without a fiscal block); only a listed file that fails is an error. Web builds verify every file before publishing, so this concerns files damaged in transit or on a desktop disk. Tests: dataManifest-errors, gvarLoader-strict, loadBVARData-country; checked in a browser with a deliberately damaged file. Web only so far; not in a desktop installer.

    [4.0.0] - 2026-10-05 — DATA AND MODEL SEPARATED FROM THE APP (IMF circulation)¶

    Data and model updates no longer need a new app version, and the dates now come from the data.

    • Data packs. Everything the app shows lives in a data pack (app/public/data + manifest.json with every file's SHA-256 and size). The app verifies every file before use and refuses an incompatible or damaged pack with one clear full-screen message.
    • Desktop updates without reinstalling. Settings → Data pack → Open data folder: unzip an update pack there and press Reload. An update pack carries only the changed files (a quarterly data shift: about 3 MB zipped) and is accepted only if every file it reuses matches the app's built-in data. Rollback = remove manifest.json from that folder.
    • The data carry their own calendar. Each history file records its first quarter; the last quarter is always first quarter + rows − 1. There is no date setting to edit or forget.
    • Fixed: the one-quarter mis-dating since 22–23 Sep 2026. The September model updates replaced the data with exports ending 2025Q4, silently dropping the July 2026Q1 shift, while the date label stayed at 2026Q1. For 35 economies the charts were dated one quarter late, the 15 seasonal economies' quarterly pattern was applied one quarter off, and the published 2026Q1 data were missing. 4.0.0 ships the current model with the 2026Q1 shift re-applied (US observed, 161 published values pinned, the rest nowcast), every economy genuinely ending 2026Q1 and checked against FRED/Eurostat and the estimation panels.
    • Model updates re-apply the shift automatically. npm run data:model-update -- --then-shift dates fresh exports from the estimation panels, re-stamps and verifies the pack, and brings the panel to the latest published quarter. A calendar check against the estimation panels runs on every build.
    • Refresh scripts run unattended. npm run data:shift -- --asof <Q> --commit runs the whole chain, verifies it, and cuts update packs for every recorded app release. npm run data:auto is the cron entry point. Git commit and push stay human decisions.
    • Also fixed: a shift no longer re-publishes dropped economies (Argentina, Israel, Russia) from the staging folder; realized-data pins are dated per economy (euro members were compared one quarter off); "annual re-estimation due" now looks at the model's estimation end, not the panel; the vintage monitor labels a comparison "pure data shift" only when it is the same model.
    • Docs: docs/UPDATE_MANUAL.md, the complete guide for users and the maintainer.

    Known and open (not changed in 4.0.0): the euro members still run the 19 Aug 2026 model generation; the US history keeps pre-revision values before 2025Q4 (the 2025Q4 growth point mixes vintages); the euro-area raw 5-year policy-rate forecast moved from 4.86% to 0.80% with the 2026Q1 data; US debt-target steering ends about 5 pp off target at the 5-year horizon.

    [3.3.0] - 2026-08-27¶

    The DVAX release — a units-consistent foreign-demand pass-through prior, a full 35-bloc re-estimation, a coherent euro area, and a world-panel reconstruction fix.

    The country VARs used to shrink each foreign "star" coefficient toward zero, so a bloc carried no long-run tie to trade-weighted foreign demand — and the re-centred level model that tried to add one drifted (the foreign-demand star climbed without bound). This release replaces that with a difference-form DVAX prior on the foreign-demand star (ROWDEM → GDP only; inflation and the foreign-rate star keep the standard prior). The prior re-centres the pass-through onto each bloc's value-added export share μ_i (OECD–WTO TiVA), in units that check out: because ROWDEM is an annualized growth rate and domestic GDP carries the Minnesota random-walk prior (its equation is a quarterly first difference), the prior mean is +μ_i/4 on lag-1 and −μ_i/4 on lag-2 — a difference whose coefficients sum to zero, so the channel injects no permanent drift, only transitory co-movement. See the manual, §"Foreign-demand pass-through" and the Known-issues note.

    • Full 35-bloc re-estimation with the difference-form prior, US endogenous, lags=3. The coupled solve stays contractive: dense-eig ρ(M) = 0.966 (< 1). The US credit-spread global solve reproduces the paper's ballpark (US −2.43, EA −1.82, JP −3.44, World −1.85 pp growth troughs).
    • Coherent euro area: all 17 euro-member blocs re-estimated so the area aggregate and its members are consistent; member→EA feedback (a member's GDP/prices reach the aggregate) verified.
    • World-panel reconstruction fix: the World GDP/inflation read-outs drew the baseline line from the shipped panel but the scenario line from the solver's recomputed baseline; for a few explosive-companion blocs those diverge, so a null scenario spuriously "jumped." The scenario is now built as baseline + Σ ω·(growth of the solver delta), sharing one baseline — a null scenario returns exactly the baseline. (Model-agnostic; fixes the deployed app too.)
    • Docs & housekeeping: manual updated (difference-form prior + explosive-baseline known issue), MkDocs track merged, stale MFFM_* LaTeX artifacts removed, human-operations instructions refreshed.
    • Shipped in two steps: this build carries the 200-draw core (validated); a 1000-draw band refresh follows. Two tests are skipped with TODO(dvax-1000) — the JP spread-scale golden value (re-verify vs DVAX-MATLAB) and the CN external-satellite CA anchor (re-anchor external_meta to the DVAX baseline) — both genuine re-estimation consequences in secondary features, documented not bumped.

    Added¶

    • Drivers panel (EXPERIMENTAL, model-conditional) — app/src/components/controls/DriversDrawer.tsx (UI) and app/src/lib/compute/driversDecomp.ts (engine). The drawer takes the scenario path the app is currently showing — or an imported external-forecast combination — and asks a chosen DSGE model from the Macroeconomic Model Base which sequence of that model's own structural shocks would have produced it over the first H = 12 forecast quarters. It draws the answer as a stacked contribution chart in the same units as the main panel, with an explicit grey residual for the part the named shocks cannot reproduce. The object solved is the deconvolution z_o(t) = Σ_k Σ_{τ≤t} R_{k,o}(t−τ)·ε_k(τ) + u_o(t), where z is the scenario's level deviation from baseline mapped into the model's observable space, R_{k,o}(h) is observable o's impulse response to shock k at horizon h, and u is the residual; stacking gives a (q·H) × (K·H) response matrix Θ over q watched observables and K named shocks, each (o,k) block lower-triangular Toeplitz. The claim is model-conditional: it says what mix of model M's shocks reproduces the displayed path, not what caused it, and it is not model-free shock labelling. Its validation is same-model recovery — generate a path from a model's own known shock sequence, decompose it under that same model, compare the recovered contribution paths — so the numbers speak to the estimator, not to the model and not to the world. A "Drivers" button with an amber exp badge appears in the scenario-action cluster once any displayed, isolated or coupled deviation (or an active external combination) exceeds 1e-9; the drawer does not solve while closed.
    • The estimator: a column-normalised min-norm least-squares deconvolution. Every column of Θ is rescaled to unit response energy before the solve (columns below 1e-12 keep a scale of 1 so they stay inert), the row weights w = 1/√(1+me) of any added observable are applied to both Θ and z, and the ridge normal equations at λ = 1e-8 · mean(diag ΘᵀΘ) are LU-factored once and then refined by two iterative sweeps against that same factorisation, so the iterate stays in range(Θᵀ) and converges to the minimum-norm least-squares solution. The normalisation is an equal-response-energy prior across shocks: SW07's stacked three-observable H = 12 response norms run from 1.28 (interest_) to 13.84 (epinf), roughly an order of magnitude apart, so the raw solver prices the small-response monetary shock out of its own attribution. In identified configurations the rescaling is a pure reparameterisation (the licence fixtures still recover to ≤ 1e-6); underdetermined, it removes the bias — at three observables SW07's mean off-class leakage falls 32% → 5%. Contributions are computed back through the raw Θ and the un-normalised shocks, so neither the column scaling nor the row weights touch the reported bars. Every observable maps into the main panel's display space through a linear operator (a gain or a scaled first difference), so bars, residual and baseline reproduce the scenario line to 1e-8. The engine reports exact-fit when rank(Θ) ≥ q·H and residual-able otherwise; in the exact-fit regime the residual is identically zero by construction and only becomes a test once observables are added.
    • The two rules the validation bench licenses, enforced in the engine and in the UI. First, the budget rule: at q watched observables at most q shocks may be named. decompose throws on K > q and the drawer disables every un-named chip at the budget. The budget is 3 + addedObs on the US bloc, where SW07's and CMR14's native columns are available, and 3 everywhere else. Observables that are invertible linear transforms of one already watched (SW07 dy, pinfobs, robs; CMR14 gdp_obs, inflation_obs, Re_obs) are excluded from the addable list, because adding one would raise the budget while buying no new rank and the identification the rule promises would be fictitious — pinned against the data, not a curated list, by a test requiring each of the four legitimate SW07 addables to buy exactly H = 12 new rank and each excluded transform to buy exactly zero, alone and together. Second, the collinearity flag: shock pairs whose unit-normalised stacked three-observable H = 12 response paths satisfy |cos| > 0.95 are precomputed at build time and warned on whenever both members are named, with the measured |cos| quoted. The split within such a pair is not identified and must be read jointly; the one-click "Use all" selection is greedy in the model's own shock order and skips any shock collinear with one already picked.
    • The class view, licensed at exactly one configuration on three coordinates. classViewLicensed(model, observableKeys, namedShocks) returns true only for US_SW07, with all seven observables watched (output, inflationq, interest, dc, dinve, dw, labobs) and all seven of its class-map shocks named (interest_, eb, fiscal_, eqs, ea, epinf, ew). That is the single cell of pipeline/bench_class_recovery.m that passes both pre-stated criteria under the shipped solver — recovered class totals correlating ≥ 0.95 with the truth in ≥ 90% of active-class instances over 20 seeds, and mean off-class leakage ≤ 25% — and it passes them with a perfect diagonal (Monetary / Demand / Supply each 100%, 0% leakage). The bench held all three coordinates fixed, so the predicate gates on all three: un-naming a single shock revokes the class view, since that shock's energy is redistributed over the classes that remain, which is precisely what the leakage criterion measures. Everywhere else the Classes toggle is greyed with its reason and the view falls back to Groups — the models' own shock names. The licence says the estimator recovers class totals when the truth is generated by that same model at that configuration; it says nothing about whether SW07's classes are the right classes, and nothing about the world.
    • The FRB/US census lenses (US_FRB22, US_FRB22_var), each with its 54 native shocks grouped into empirical collinearity clusters. Both lenses carry interest_, fiscal_ and 52 _aerr equation-residual shocks, none dropped, and their individual columns are not separable in the three common observables: 109 of the 1,431 shock pairs exceed |cos| = 0.95 for US_FRB22 and 117 for the VAR-expectations variant. The drawer therefore groups by the structure the response space actually has: connected components of the |cos| > 0.95 graph (23 clusters for US_FRB22, 21 for US_FRB22_var), each labelled by its largest member's equation. Collinearity is not transitive, so members are chained through collinear links rather than mutually parallel — the composite column is the genuine first principal component of the member set, not a proxy for an already-parallel bundle, and the budget counts clusters, not members. The class view is refused for FRB/US by the bench at the only observable set it can run at (three observables; both solvers fail both criteria), and there is no seven-observable FRB/US configuration, since the native mapping exists only for SW07 and CMR14. What backs each lens is a build-time scan instead: every possible cluster triple is run through the shipped solver over 20 sparse-truth seeds against a 1e-6 recovery criterion, and the shipped default is picked deterministically among the passers — 123 of 1,771 triples pass for US_FRB22 (default [hqlfpr, interest_, pcer_l], worst error 2.53e-9, covering 19 of 54 shocks) and 122 of 1,330 for US_FRB22_var (default [eco_l, interest_, ki_l], worst error 1.32e-7, covering 12 of 54). A full-rank Θ is not evidence that a triple is usable — most are badly conditioned while passing the rank test — so the drawer warns whenever the user leaves the validated default naming. Under Customize → "Experimental: raw shocks" individual _aerr shocks can be decomposed instead of clusters (the greedy non-collinear list is 26 of 54 for US_FRB22), still subject to the budget.
    • The census IRF payload — app/public/data/dsge/census/. A 36 KB index.json (schema: "gmaps-drivers-index/1") carrying the model menu, each entry's usable and dropped shocks, its collinear pairs, its clusters and default naming where applicable, the shock-class maps copied verbatim from pipeline/_shockbench/class_maps.json, and a sha256 per file; plus eight census IRF files (CA_LS07 47 KB, BRA_SAMBA08 123 KB, EA_SW03 200 KB, EA_SWW14 217 KB, HK_FP13 218 KB, UK_SM11 231 KB, and the two ~10.7 MB FRB/US lenses). Four further models are indexed rather than copied, from the existing irfs tree: US_SW07, US_CMR14, US_FRB08 and the menu-hidden US_FRB22_mcap. index.json is fetched once per session on the first drawer open and each model's IRF file once on selection, both cached in component state with a per-model retry on failure, so the default lens costs 36 KB + 215 KB and either 54-shock FRB/US lens a further ~10.7 MB. Regenerated by node app/scripts/build_drivers_index.mjs, which refuses to ship a census file whose sha256 does not match pipeline/census_irfs/MANIFEST.json.
    • The validation record travels with the code — pipeline/bench_simple_decomp.m and pipeline/bench_class_recovery.m (both print to stdout; the committed docs/paper/simple_decomp_results.txt and docs/paper/class_recovery_results.txt are captured transcripts) and pipeline/_shockbench/class_maps.json. bench_simple_decomp.m established the budget and collinearity rules on eight models — US_SW07, US_CMR14, EA_SW03, EA_SWW14, CA_LS07, HK_FP13, BRA_SAMBA08, UK_SM11 — with SW07 at its native seven observables and all seven usable shocks fully identified (rank 84/84, noiseless recovery 3.6e-15, 100% at 1% noise). Note that pipeline/census_irfs/ is not on this branch, so neither bench re-runs here in full: only two of bench_simple_decomp.m's eight rows and four of bench_class_recovery.m's five model rows have their inputs on the branch.
    • 26 licence tests (app/src/__tests__/compute/drivers-decomp.test.ts 4, -v2.test.ts 7, -v3.test.ts 15), run in the fast npm test gate. They assert the class licence against literal bench coordinates rather than against the shipped constants, with a negative case for each of the seven droppable shocks, so widening either constant turns the test red; check index.shockClasses against class_maps.json verbatim and every shipped sha256 against the bytes, turning the hand-run builder's checks into CI gates; pin the BVAR-panel → model-observable mapping with hand-computed expectations; and require each addable observable to buy exactly H rank while each excluded duplicate buys none.
    • docs/drivers-decomposition.md — the methodology write-up (mkdocs nav → Methodology), with the user-facing walkthrough added to USER_GUIDE.md and the manual.

    Changed¶

    • The SW07 and CMR14 IRF files are regenerated with their full native shock sets — app/public/data/dsge/irfs/US_SW07/SW.json (215 KB) and .../US_CMR14/SW.json (1.79 MB) — which is what makes the seven-observable mode possible on the US bloc. The interest_ and fiscal_ columns the existing policy-counterfactual feature reads are unchanged to ≈5e-11 (re-export rounding only), so the monetary and fiscal counterfactual paths are unaffected.

    Not established¶

    The feature is badged experimental in the UI and should be treated as experimental in every document that cites it. Its claim is model-conditional throughout: a different lens gives a different mix, and the lenses are not equally validated. The validation is same-model recovery, which measures the estimator rather than the model or the world. In the exact-fit regime the residual is zero by construction and is not evidence that the named shocks explain the path. The shares strip below the chart is a norm share of contribution paths, not a variance decomposition, so it always sums to 100 and can never show two contributions offsetting each other. FRB/US clusters are empirical, not economic. And the chart's "Deviation from baseline" view always draws the panel's rate deviation, while the main panels' "% vs base" mode defaults to a level sub-mode, so the auto-follow can put the two in different units; the axis title states which.

    Technical Notes¶

    • All BVAR computation (Kalman filtering, DK smoothing, conditional forecasting, uncertainty simulation) runs entirely client-side in the browser using TypeScript and Float64Array-backed matrix operations. No server round-trips are required after initial data loading.
    • Pre-computed data totals approximately 152 MB, served as static JSON from /public/data/. This includes BVAR posterior estimates for 6 countries, 726 DSGE model-rule IRF files, and the model/rule catalogs. The US companion_draws.json (posterior simulation draws for full uncertainty) is loaded lazily only when the user clicks Compute.
    • The unconditional DK smoother result is cached and reused across conditioning changes to avoid redundant computation. A 30ms debounce is applied to conditioning path updates.
    • Built with Next.js 14.2, React 18, Zustand 4.5 for state management, Plotly.js for interactive charts, and SheetJS (xlsx) for Excel I/O. Styled with Tailwind CSS. Tested with Vitest.
