    How to update / re-estimate the models¶

    4.0 (Oct 2026): every re-export must be DATED before anything else. A model export ends each history at the estimation end and carries no dates. Skipping the dating is exactly what happened in Sep 2026: two re-exports silently undid the July 2026Q1 shift and every chart was dated one quarter late. There is no DEFAULT_LAST_HIST_DATE any more — never set a date by hand. - Export that ends at an older quarter than the latest published one (the pre-2026 practice: estimate to a year end, then shift): npm run data:model-update -- --then-shift dates the histories from the estimation panels, re-stamps and verifies the pack, and shifts to the latest published quarter. - Export fitted to the latest published data (the October 2026 practice — ragged edge, no shift needed): node scripts/stamp_calendar.mjs, then the chain in the ★ section below (nowcast of the ragged edge, baselines, bands, data pack under a new pack id).

    Operator guide: UPDATE_MANUAL.md §7.

    This is the operational runbook for re-estimating the GVAR macro blocs and rebuilding the fiscal block, then porting, verifying, and deploying. The platform today (data pack 2026Q2-reest-20261008b, deployed 2026-10-08): an endogenous-US, 35-bloc GVAR estimated by an iterative GVAR-EM loop (coupling ρ(M) = 0.971875), the 17 euro members estimated one at a time, and a 4-variable fiscal block (with an exact-residual SFA) in 41 economies. Every panel is rebuilt from published sources with no fills, to 2026Q2. The ★ section below is the current procedure; §0–§6 keep the older detail and are marked where they differ.

    Bloc count (35). The coupled set is the US, the euro-area aggregate and 33 Rest-of-World blocs, including HK SG RO PE PH (added with the FSAP-coverage expansion; AE was not viable: only annual real GDP exists and we do not interpolate). Russia, Argentina and Israel were dropped. With the 17 euro members that is 52 economies. The bloc list is data-driven from weights_full_38.json (estimation; it holds the same 35 blocs — the name is historical) / weights_24bloc.json (the app's copy, fetched from the data pack); see §0 and §1.2. To add a brand-new bloc from scratch, see the new-bloc recipe in ADDING_A_COUNTRY.md (build_newbloc_panel.py + build_globals_new_blocs.py).

    Scope. This covers re-estimation and data refresh of the existing blocs. To add a brand-new country or RoW bloc, see ADDING_A_COUNTRY.md (this runbook reuses the same port / verify / deploy gate). For the live methodology, see ARCHITECTURE_FOR_AI.md and fiscal-block-methodology.md.

    The deployed tool is live at the /bvar-scenario path of the academic website, hosted on GitHub Pages (the matyasfarkas/starter-hugo-academic Hugo Academic site), and at gmapsmodel.com (Netlify).

    Golden rules. Exact MATLAB replication when porting (no shortcuts). Use real observed data, never synthetic placeholders. Never deploy without a green gate. Do not hand-edit the GVAR topology (IDX/W/ROW_COUNTRIES in gvarSolve.ts) — it self-configures from the deployed specs + weights.

    1. Re-estimate the GVAR macro blocs (GVAR-EM loop)¶

    1.1 What the loop does¶

    pipeline/export_bvar_gvar24_loop.m is the canonical GVAR-EM (Expectation–Maximization) estimator:

    1. For each non-US bloc, build its 3 RoW "star" vars (ROWDEM/ROWINF/ROWFIN) = trade-weighted averages of partners' real-GDP growth / inflation / short rate, renormalised over the partners present each quarter (unbalanced panel). COVID + no-partner quarters start NaN.
    2. Estimate each bloc by cgl_bvarV5([domestic | 3 stars]) — the COVID-as-missing Gibbs sampler; the DK (Durbin–Koopman) smoother fills the missing star + COVID quarters → a completed matrix per bloc.
    3. Loop (Jacobi): recompute every bloc's stars from partners' completed data, re-estimate all blocs in parallel (parfor), until the foreign components converge (max |Δstar| < TOL).

    Key facts encoded in the script (do not change without re-validating):

    • US_ENDOGENOUS=1 (env). With a weights.US row present, the US is folded into the convergence loop and re-estimated with its own 3 RoW stars (n=40 today: domestic + fiscal + globals + 3 ROW*_US). It drives RoW and receives RoW→US feedback. A no-stars bootstrap still runs first only to seed partners' iter-1 stars (it is discarded, not exported).
    • COVID window is the argmin of ΔGDP restricted to 2019Q4–2021Q1 (a global argmin misfires, e.g. KR's 2008Q4 GFC drop), then ± quarters around it are NaN'd → DK-imputed.
    • MAXIT=12, TOL=0.03 (MC noise floor ≈0.13 — unless GVAR_FIXHYPER=1, production since Oct 2026, which holds (λ, μ) at the mode with aligned random numbers during the sweeps so the loop really converges; the 2026 run used MAXIT=30 and converged at sweep 6, then ran one full-MH pass). MAXIT=1 ⇒ single-country (separated): one-shot historical stars, no coupling iteration.
    • Scale traps (already correct in-script, listed so you don't "fix" them): stars are 4·Δ(100·log) not 400·; the completed panel is mean(Xcond,3); CN GDP is real (since the 2026-06 CN-only re-estimate; NOMINAL_GDP_BLOCS empty) → read directly, not deflated by subtraction; leading star NaN is back-filled (not under GVAR_NOFILL=1, production since Oct 2026: every gap stays missing and is drawn by the sampler); the _US column is dropped (no-op on _glob inputs); the short rate is optional (CH/NO have none → excluded from partners' ROWFIN); AR hyperinflation excluded from partners' INF/FIN (kept in DEM).

    1.2 Run it¶

    From the repo root (MATLAB with the Parallel Computing Toolbox; the loop uses parfor):

    # Full 35-bloc endogenous-US run — the October 2026 production settings (about 1 h 40 min).
# Exact script: docs/reest-2026/runs/run_gvar35b.sh
BVAR_DIFF_GP=1 US_ENDOGENOUS=1 NDRAWS=1000 MAXIT=30 BVAR_SEED=1 GVAR_FIXHYPER=1 GVAR_NOFILL=1 \
  GVAR_WEIGHTS_FILE="$PWD/app/public/data/bvar/gvar/weights_full_38.json" \
  GVAR_DUMMY_BLOCS="CL CN CO CR EA ID IL IN IS JP KR MX NO TR UK ZA HK PE" \
  BVAR_RAWDATA_DIR="$PWD/pipeline/country_rawdata" GVAR_OUTDIR=<run>/gvar35 GVAR_WORKSPACE=<run>/gvar35_ws.mat \
  matlab -batch "run('pipeline/export_bvar_gvar24_loop.m')"

    weights_full_38.json holds the 35 shipped blocs (the name is historical; Israel is still in the dummy list but no longer estimated). GVAR_DUMMY_BLOCS must be passed explicitly to add HK+PE to the seasonal-dummy set — the script's own default is the 16-bloc set (§1.3), so without the override the two new NSA-seasonal blocs would estimate without their quarterly dummies. Time-varying weights (weights_timevarying.json) are picked up automatically for the estimation stars when present (§1.3(c)) — no env flag needed.

    Useful env overrides (for fast subset validation before committing the multi-hour full run):

    # Fast smoke: 3 blocs, few draws, 1 iteration (single-country, no coupling)
BVAR_GVAR_BLOCS="US EA JP" NDRAWS=200 MAXIT=1 US_ENDOGENOUS=1 \
  matlab -batch "run('pipeline/export_bvar_gvar24_loop.m')"

    Outputs. Each bloc's full deployed JSON contract to GVAR_OUTDIR (default /tmp/gvar24_export/<CC>/) (spec, companion_mean, companion_draws, historical, historical_levels, baseline, baseline_levels, transformations, and under GVAR_NOFILL=1 estimation_mask.json — the cells the sampler drew, which the app shows as model estimates). The full estimation state is also saved to /tmp/gvar24_workspace.mat before export, so an export-only bug is a cheap re-export, not a re-estimation.

    Watch the console. Each iteration prints max star change vs tol; convergence prints CONVERGED. Each export prints n, draws, and the 1-quarter GDP growth (GDP1q) — confirm it is a sane number, not NaN or a collapsed flat line.

    If a bloc returns a singular / NaN SIGMA, the data is the cause (a leading NaN in a discontinued series, or near-collinear national-accounts identities). Fix the raw DataRaw_<CC>_glob.json, not the estimator. With COVID imputed the empirical-Bayes lambda optimum is well-behaved (~0.24–0.56); a fixed lamfix is not needed (and pinning one with noc/sur both fixed makes lambda degenerate to NaN).

    1.3 Seasonal-v2 estimation (dummies · two-stage E-step · time-varying weights)¶

    Three estimation features (2026-07-17, all env-gated, all byte-identical no-ops when off) travel with the loop. They matter for the NSA-seasonal and coupon-lumpy blocs.

    (a) Quarterly seasonal dummies — GVAR_DUMMY_BLOCS. Blocs with a genuinely NSA-seasonal series (calendar-R²≥0.40 and display-amplitude ≥2 on the panel scan — NSA HICP/CPI, unemployment, house prices, some SFA/GOV series) plus every even-interest bloc (§2.3) get quarterly dummies D=[q==2, q==3, q==4] (Q1 the base) in each equation, so the seasonal cycle is a bounded deterministic cycle rather than a spurious near-Nyquist explosive root. The default coupled set (verified pipeline/export_bvar_gvar24_loop.m:49–53) is:

    CL CN CO CR EA ID IL IN IS JP KR MX NO TR UK ZA        # 16 coupled blocs (GVAR_DUMMY_BLOCS default)

    The 38-bloc run passes 18. The two new NSA-seasonal FSAP blocs — HK and PE — are not in the in-script default, so the production 38-bloc command explicitly sets GVAR_DUMMY_BLOCS="… HK PE" (§1.2). SG/RO/PH do not carry the dummies (they did not clear the NSA-seasonal panel scan). Verify the console print GVAR-EM: seasonal-dummy blocs: … lists all 18.

    plus the six euro members ES IT GR PT SI BE handled by the standalone estimator (pipeline/export_bvar_euro_redesign.m:44–49, env EURO_DUMMY_MEMBERS). Mechanism (verified BVAR/MFBVAR/Support/BVAR.m:4–6,63,74): the design row is x=[1, D, y_{t-1},…,y_{t-p}], so betahat has k = 1 + nsr + n·lags rows laid out [constant; γQ2; γQ3; γQ4; B_1;…;B_p] with nsr=3 ("seasonalRows"); the dummy coefficients carry the diffuse intercept prior (Vc=1e6) and are zeroed in the sum-of-coefficients dummy observations. cgl_bvarV5.m receives the per-row quarter-of-year via the 'qoy' vararg (the DK simulation-smoother artificial path carries the seasonal term, and the forecast simulation continues the q-of-year cycle). exportbloc ships seasonalRows in spec.json + companion_mean.json (and qoyNext for seasonal blocs); legacy nsr=0 blocs are bit-for-bit unchanged.

    Phase rule (do not hand-carry qoyNext). The app always recomputes qoyNext from its own date grid via dates.qoyNextOf(country) (= the quarter after lastHistOf, wrapped 1..4; app/src/lib/dates.ts:88–89), never the shipped estimation-grid qoyNext (which sits one quarter behind after the production shift; app/src/lib/compute/gvarSolve.ts:417–422). The shipped qoyNext is only for the node pipeline scripts (qoyNextOverride).

    (b) Two-stage E-step — GVAR_POLISH_EXACT (default OFF for the coupled system) + CGL_FIXED_COMPANION. The outer Jacobi/EM loop runs the DK imputation with a fixed-companion E-step (cgl_bvarV5 'fixedcomp',1) so consecutive sweeps share random numbers (common random numbers) and the star fixed point contracts to TOL (export_bvar_gvar24_loop.m:159–195). The shipped coupled models use the fixed-companion posterior from that converged loop. A textbook exact data-augmentation E-step (companion rebuilt from the current draw every Gibbs sweep — the open-issue-#4 fix, env CGL_FIXED_COMPANION=0 / 'fixedcomp',0) is available as an optional final polish sweep at the frozen converged stars (:197–217, GVAR_POLISH_EXACT=1) but is OFF by default: exact DA (i) breaks the CRN contraction if used inside the loop (a ~0.6–1.8pp star-churn floor that never meets TOL) and (ii) marginally raises companion persistence, which lifts the coupled operator's ρ(M) above 1 (measured 1.0067 with the polish vs <1 without) → non-contractive pinned-scenario spillovers. So keep it off for the coupled ship; enable GVAR_POLISH_EXACT=1 only for a standalone exact-DA reference posterior. Single-bloc estimators (euro members) run exact DA directly and are unaffected.

    (c) Time-varying trade weights — GVAR_TV_WEIGHTS + weights_timevarying.json (now promoted for estimation). When app/public/data/bvar/gvar/weights_timevarying.json exists and GVAR_TV_WEIGHTS≠0, buildstars applies each quarter's calendar-year weight row (clamped to the file's span; a partner absent from a year's row gets weight 0, absorbed by the existing per-component renormalization — export_bvar_gvar24_loop.m:55–72,269–318). Absent artifact or GVAR_TV_WEIGHTS=0 ⇒ the static row everywhere (byte-identical legacy).

    • Source it: pipeline/fsap_expansion_staging/weights/build_weights_timevarying.py pulls IMF IMTS via api.imf.org SDMX 2.1 (dataset IMTS, indicators XG_FOB_USD+MG_CIF_USD, key COUNTRY.INDICATOR.COUNTERPART.A), annual bilateral X+M 1995–2024 over 39 blocs (the 38 coupled + AE), per-year row-normalized (zero diagonal, <0.05% shares dropped) → weights_timevarying.json (+ weights_latest.json = 2024, + weights_validation.json).
    • Promote it: copy the staged weights_timevarying.json into app/public/data/bvar/gvar/ — done on the seasonal-v2 branch (the artifact is now present there), so the loop reads it and GVAR_TV_WEIGHTS is active by default during estimation. weights_full_38.json (the static coupling file) is the 2021–23 average of this same TV panel over the 38-bloc set.

    Note the solve-time coupling still uses the static file (weights_24bloc.json) — the estimation stars are time-varying, but the browser (I−M)⁻¹ operator is built from the static/current-year weights; swapping the coupling to the latest year would be a separate, user-approved step. Honest empirical shape (validation artifact): the US→China trade share rises to a mid-2010s peak (~0.17) then FALLS after the 2018 trade war (~0.12 by 2024), while US→euro-area does not decline — it rises (~0.178 by 2024). Document the reversal; do not claim a monotone CN-up / EA-down trend.

    (d) Seasonally-adjusted forward forecast — GVAR_NSA_FORECAST (2026-07-18). The quarterly dummies of §1.3(a) stay in estimation and the DK imputation (quarter-specific), but the shipped forward forecast is seasonally adjusted: for a seasonal (nsr=3) bloc the deterministic term uses the annual-mean dummy row [¼,¼,¼] at every step, so the baseline is c̄ = c + (γ_{Q2}+γ_{Q3}+γ_{Q4})/4 (a smooth SA path that matches cgl_bvarV5's SA Dforecast bands + the app — verified export_bvar_gvar24_loop.m:339–350, cgl_bvarV5.m:255–266). Setting GVAR_NSA_FORECAST=1 switches the forward forecast back to the quarter-specific (NSA) path (drow=[q==2,q==3,q==4]). Leave it unset for the shipped models (SA baseline). Legacy nsr=0 blocs are unaffected either way.

    1.4 DVAX difference-form foreign-demand prior (shipped in 3.3.0, rolled back in 3.4.0 — NOT in the current model)¶

    The October 2026 re-estimation does not use DVAX (no BVAR_FMEAN_MAP / BVAR_KAPPA_ROW / BVAR_NOC_EXEMPT_STARS in docs/reest-2026/runs/run_gvar35b.sh). Kept for reference.

    The 3.3.0 model re-centred the foreign-demand star only (ROWDEM → GDP; inflation and the foreign-rate star keep the standard prior) onto each bloc's value-added export share μ_i = EXGR_DVA/VALU (OECD–WTO TiVA, per-country in pipeline/mu_dvax.json). Units matter: ROWDEM is an annualized growth rate and domestic GDP carries the RW own-lag prior (its equation is a quarterly first difference), so the prior mean is +μ_i/4 on lag-1 and −μ_i/4 on lag-2 — a difference (coefficients sum to zero → no permanent drift, only transitory co-movement). Reduced form has no lag-0, so "contemporaneous"→lag-1, "first lag"→lag-2. The mechanism is a lag-aware fmean set at both prior-mean sites (BVAR_coint.m draws + cgl_bvarV5_coint.m MH target), with κ=0.15 on ROWDEM and ROWDEM noc-exempt.

    # Env flags on top of the §1.2 run (level mode: BVAR_GROWTH_SPACE UNSET):
US_ENDOGENOUS=1 \
BVAR_FMEAN_MAP=1 \                 # per-country μ from pipeline/mu_dvax.json (via the muMap arg — parfor-safe)
BVAR_KAPPA_ROW=0.15 \             # tight κ on ROWDEM only
BVAR_NOC_EXEMPT_STARS=1 \        # ROWDEM noc-exempt
NDRAWS=1000 MAXIT=12 \
GVAR_WEIGHTS_FILE=<abs>/app/public/data/bvar/gvar/weights_full_38.json \
GVAR_OUTDIR=/tmp/gvar24_dvax \
matlab -batch "run('pipeline/export_bvar_gvar24_loop.m')"

    Coefficient gate (before trusting the run): per bloc, exported betahat, GDP equation — ROWDEM lag-1 ≈ +μ_i/4, lag-2 ≈ −μ_i/4 (US ±0.024), lag-3 ≈ 0; ROWINF/ROWFIN unchanged. The Minnesota lag decay (α=2) makes the lag-2 prior ~4× tighter than lag-1, so lag-1 is the more data-pulled of the two — expected, not a defect. Then the usual gates: dense-eig ρ(M) ≤ 0.985 (the stored JS power-iteration under-reads ~0.003 — always dense-eig; §4.1), and the US-spread global solve in the paper ballpark. Euro members are re-estimated separately (CC=<code> matlab -batch "run('pipeline/export_bvar_euro_redesign.m')" per member, staging → §3 port). Full config: docs/dvax-rowdem-level-config.md.

    Honest limit. The prior shapes the pass-through to domestic GDP, not ROWDEM's own dynamics — the star can still drift under its RW prior, but because the net pass-through b¹+b²≈0, domestic GDP inherits almost none of it (the level system stays anchored). A handful of EM blocs (BR/CN/JP) keep a marginally-explosive own companion; the world read-out is delta-aggregated so it is immune (§3.3 / the manual's Known-issues note).

    2. Rebuild the fiscal block (4-variable, exact-residual SFA)¶

    Since October 2026 the fiscal block of all 41 fiscal economies is built inside the panel build from each source registry's fiscal section (pipeline/sources/registry/README.md: revenue, total expenditure, interest, gross debt and nominal GDP from their publishers; a genuine GDP deflator column; even-coupon economies use trailing 4-quarter interest ÷ debt). The per-country builders below are the older path; the identities (SFA as the exact residual of the app's debt recursion) are unchanged.

    The fiscal block carries 4 estimated BVAR variables (originally for US, EA, JP, UK, CA, CN):

    ID Meaning Units
    FREV_GDP revenue / GDP × 100 % of GDP (annual)
    FPEXP_GDP primary expenditure / GDP × 100 % of GDP (annual)
    EFFI effective interest rate = net interest / lagged gross debt × 100, annualised % p.a.
    SFA stock-flow adjustment % of GDP (annual)

    SFA is the exact residual of the app's debt recursion. The build script rearranges the exact recursion in app/src/lib/compute/fiscalAccounting.ts (computeFiscalBlock, ~line 169) onto the observed gross-debt/GDP path so that the BVAR's SFA column closes the recursion to machine precision (it captures the federal-flows-vs-gross-debt perimeter seam / intragovernmental holdings — the deficit–debt discrepancy):

    d_t = d_{t-1}·(1 + EFFI/400)/(1 + gNomQ/100) − pb/4 + sfa/4        (% of GDP)
pb     = FREV_GDP − FPEXP_GDP
gNomQ  = 100·log(realGDP_t/realGDP_{t-1}) + 100·log(deflator_t/deflator_{t-1})   (% per quarter)
⇒ SFA_t = 4·(d_obs_t − d_{t-1} − snowball_t + pb_t/4)

    The crucial subtlety: gNomQ is read off the same glob columns the app reads (idx.gdp/idx.deflator, stored as 100·log), as a log growth — not a simple nominal SAAR (seasonally-adjusted annualised rate) growth. Building it the app's way is what drives the closure error to < 1e-6 (an interpolated COVID value can never equal the residual, so COVID quarters are set NaN for the Gibbs to impute).

    fiscal_meta/<CC>.json carries idx = {gdp, deflator, revenue, primaryExp, effRate, sfa} (note: there is no debtService — DSVC was reverted to EFFI), d0, and sfaDefault. The debt/GDP projection now carries the forecast SFA forward (idx.sfa set ⇒ the recursion reads the estimated SFA level path with its own dynamics + bands, instead of defaulting SFA to 0).

    2.3 Even-coupon EFFI rebuild (coupon-lumpy RoW fiscal blocs)¶

    The wider RoW fiscal blocs are built by pipeline/build_fiscal22_columns.py (which appends the same four FREV_GDP/FPEXP_GDP/EFFI/SFA columns to a bloc's _glob.json). Eight of them pay interest on an annual/semiannual coupon calendar, which made the single-quarter EFFI a near-Nyquist sawtooth (the diagnosed root cause of the EFFI/SFA jaggedness). For these blocs the builder distributes the coupon evenly before estimation (verified pipeline/build_fiscal22_columns.py:58–100,178–181):

    EVEN_INTEREST = {CL, CO, CR, ID, IL, MX, TR, ZA}     # coupon-lumpy blocs (calendar-R²>0.5 & CV>0.25)

    even_distribute_years() replaces the 4 quarterly interest payments within each complete calendar year by their mean (annual total preserved exactly; a trailing partial year uses the trailing-4Q mean), so EFFI = 400·evened_interest_t / debt_{t-1} becomes the accrual borrowing cost. Primary expenditure keeps the raw interest (te − intr = true non-interest spending), and the exact debt-identity residual SFA absorbs the genuine cash-vs-accrual timing — which is why these eight blocs also carry seasonal dummies (§1.3). The debt identity still closes to ~1e-14, and the sawtooth companion root moves off −1 (e.g. ZA −0.973→−0.634). Full mechanism + the before/after numbers: fiscal-block-methodology.md. Rebuild is --force (the columns already exist in the panel):

    3.2 Regenerate the GVAR coupling artifact (MANDATORY after any bloc data change)¶

    The browser solves the cross-country fixed point x = (I−M)⁻¹ d from a pre-shipped coupling artifact. At this scale the in-browser inverse is many minutes — pre-shipping is mandatory, not an optimisation. With the endogenous US the artifact is the augmented (stars ++ US-global) operator. The dimension is #blocs·60 + 80: the shipped 35-bloc artifact (pack 2026Q2-reest-20261008b) is dim = 2180 (35·60 + 80), ρ(M) = 0.971875 (rhoSpectral in coupling_default.json.gz). (Earlier: 33 blocs, dim 2060, ρ 0.945494; September 2026, 35 blocs, ρ 0.957724.) Read the live dim/rhoSpectral off the artifact header after regen (§4.1); what is load-bearing is that ρ(M) < 1. Keyed to the data by modelSig.

    From app/ (the script builds M in JS, then inverts (I−M) via MATLAB BLAS — the invert_coupling.py NumPy path is the no-MATLAB fallback). Use vite-node, not node (the script imports the TS compute modules):

    cd app
npx vite-node scripts/precompute_gvar_coupling.mjs

    It writes the gzipped app/public/data/bvar/gvar/coupling_default.json.gz directly (the plain .json is removed — at this bloc count it exceeds GitHub's 100 MB per-file limit; gzip ≈ 36 MB at 35 blocs). The data-pack manifest records the hash of the weights the coupling was built from, and the app ignores a coupling whose weights do not match the served ones. The loader decompresses it via the browser's native DecompressionStream. The artifact is keyed to the data by modelSig, so it MUST be regenerated whenever any deployed bloc changes — a stale artifact (modelSig mismatch) is rejected and the app falls back to the slow path.

    3.4 2026Q1 rebase (shift the display origin without re-estimating) — history¶

    3. 4.0: there is no date to set. The appended row is dated by the history's own calendar (firstQuarter + rows − 1). In practice run the whole chain instead of the two scripts: npm run data:model-update -- --then-shift (after the re-export), or npm run data:shift -- --asof 2026Q1 --commit.
