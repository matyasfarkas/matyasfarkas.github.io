    Drivers — model-conditional shock decomposition of a scenario path¶

    Experimental feature, model-conditional claim

    The Drivers panel is experimental and is badged as such in the tool. What it reports is conditional on the DSGE model the user selects: the mix of that model's own structural shocks which reproduces the displayed path. It is not a statement about what caused the scenario, and it is not model-free shock labelling. Read Limits of the claim before using any number from it.

    The Drivers drawer takes the scenario path the app is currently showing — or an imported external-forecast combination — and asks a chosen model from the Macroeconomic Model Base (MMB) which sequence of that model's structural shocks would have produced it over the first twelve forecast quarters. It draws the answer as a stacked contribution chart in the same units as the main panel, with an explicit grey residual for the part the named shocks cannot reproduce. This is the NAWM-II-style "filter the path through the model" exercise, run on a path object rather than by inverting a state recursion.

    It fits the tool's standing division of labour. The fiscal block and the external block take BVAR flow forecasts and derive stocks by accounting identity; Drivers takes the same BVAR path and reads it through a structural lens. In all three cases the reduced form generates the path and a separate, side-effect-free module interprets it. The authoritative implementation is app/src/lib/compute/driversDecomp.ts (the engine) and app/src/components/controls/DriversDrawer.tsx (the drawer); neither writes back into the scenario.

    The question it answers¶

    A user looking at a scenario in which output falls and inflation stays up wants to know what kind of disturbance that pattern looks like. The variance decomposition answers a population question (how much of the fluctuation in inflation is due to supply shocks?), and the historical decomposition answers a sample question (which shocks moved inflation in 2022?). Drivers answers a third, narrower question: which sequence of this model's shocks, fed into this model, reproduces the path I am looking at?

    That question has an honest answer and a dishonest one. The honest answer names the model: through the Smets–Wouters (2007) lens, this scenario is mostly a wage-markup and monetary mix; through the Christiano–Motto–Rostagno (2014) lens it is something else, because CMR14 has a financial block and SW07 does not. The dishonest answer drops the qualifier and claims to have identified what drove the economy. Everything in this page — the budget rule, the collinearity flag, the class-view licence — exists to keep the tool on the first answer.

    The exercise is validated by same-model recovery: a path is generated from a model's own known shock sequence, decomposed under that same model, and the recovered contribution paths are compared with the truth. That measures the estimator. It says nothing about whether the model is right.

    The object, precisely¶

    Let \(H = 12\) be the decomposition horizon in quarters (DRIVERS_H, driversDecomp.ts:46), \(q\) the number of watched observables, and \(K\) the number of named shocks. \(H\) is fixed: the decomposition always covers the first twelve forecast quarters, whatever horizon the main chart grid is displaying. The user supplies a deviation path \(z\) — the scenario's level deviation from baseline, mapped into the model's observable space by the conventions in Unit conventions.

    The engine solves the deconvolution

    \[ z_o(t) \;=\; \sum_{k=1}^{K}\ \sum_{\tau \le t} R_{k,o}(t-\tau)\, \varepsilon_k(\tau) \;+\; u_o(t), \qquad o = 1,\dots,q, \quad t = 0,\dots,H-1 \]

    for the shock sequence \(\{\varepsilon_k(\tau)\}\). Here \(R_{k,o}(h)\) is the model's impulse response of observable \(o\) to shock \(k\) at horizon \(h\), read straight from the shipped MMB impulse-response file, and \(u_o(t)\) is the residual — the part of the path the named shocks cannot reproduce.

    The stacked response matrix¶

    Stacking observables and quarters turns that convolution into one linear system. Define \(\Theta\) of dimension \((q\!\cdot\!H) \times (K\!\cdot\!H)\) by

    \[ \Theta[\,o H + t,\; k H + \tau\,] \;=\; R_{k,o}(t-\tau)\,\mathbf{1}\{t \ge \tau\}. \]

    Rows are blocked by observable: row \(oH+t\) is observable \(o\) at forecast quarter \(t\), with the three locked common observables first and any added natives in the order the user toggled them. Columns are blocked by shock: column \(kH+\tau\) is shock \(k\) arriving in quarter \(\tau\). Each \((o,k)\) block is therefore lower-triangular Toeplitz. The system is \(\Theta \varepsilon = z - u\) with \(z\) and \(\varepsilon\) stacked the same way, \(z[oH+t] = z_o(t)\) and \(\varepsilon[kH+\tau] = \varepsilon_k(\tau)\).

    The response \(R_{k,o}(h)\) is read as irf[shock_k][irfField_o][h + 1]. Index 0 of every impulse- response array is the pre-impact zero and indices \(1,\dots,H\) carry \(h = 0,\dots,H-1\), which mirrors the MATLAB benchmark's s.obs(2:H+1) exactly (bench_simple_decomp.m:99). The shipped arrays are all of length 21, so horizons \(h = 0,\dots,19\) are available and the engine uses the first twelve.

    Notation¶

    Symbol Meaning
    \(H = 12\) decomposition horizon, in quarters
    \(q\) observables watched (three locked common ones, plus added natives)
    \(K\) shocks — or clusters — named
    \(o\), \(t\) observable index, forecast quarter (0-based)
    \(k\), \(\tau\) shock index, arrival quarter (0-based)
    \(R_{k,o}(h)\) model \(M\)'s response of observable \(o\) to shock \(k\) at horizon \(h\)
    \(\Theta\) \((qH) \times (KH)\) stacked response matrix
    \(z\) stacked observable-space deviation path
    \(\varepsilon\) stacked shock sequence
    \(D\) \(\mathrm{diag}(\lVert\Theta_{\cdot 1}\rVert,\dots,\lVert\Theta_{\cdot KH}\rVert)\), the column-norm scaling; \(\Theta_N = \Theta D^{-1}\)
    \(W\) diagonal row weights, \(w = 1/\sqrt{1+\mathrm{me}}\) on added observables, 1 on the locked three
    \(\lambda\) \(10^{-8}\cdot\mathrm{mean}\,\mathrm{diag}(\Theta_N^{\top}W^2\Theta_N)\)
    \(u\) residual, \(u = z - \Theta\hat\varepsilon\)
    \(c_{k,o}(t)\) shock \(k\)'s contribution to observable \(o\) at quarter \(t\)

    The estimator¶

    The system is square only in the special case \(K = q\); in general it is underdetermined in the shock dimension, so the engine reports the minimum-norm least-squares solution,

    \[ \hat\varepsilon \;=\; D^{-1}\cdot \operatorname*{arg\,min}\ \lVert \tilde\varepsilon \rVert \quad\text{subject to minimising}\quad \bigl\lVert W\bigl(\Theta D^{-1}\tilde\varepsilon - z\bigr)\bigr\rVert^2 . \]

    That is the pinv solution the MATLAB benches use, computed here without forming a pseudo-inverse (decompose, driversDecomp.ts:227–362). The engine takes the Euclidean norm of every column of the raw, unweighted \(\Theta\), leaving any column with norm below \(10^{-12}\) at a scale of 1 so it stays inert rather than being amplified; divides each column by its norm to get \(\Theta_N\); applies the row weights to both \(\Theta_N\) and \(z\) where an added observable carries measurement error; forms the Gram matrix, adds the ridge \(\lambda = 10^{-8}\cdot\mathrm{mean}\,\mathrm{diag}\) (RIDGE_LAMBDA_SCALE, driversDecomp.ts:49), and LU-factors it once. It then solves the ridge normal equations and runs two iterative-refinement sweeps against that same factorisation (REFINE_STEPS = 2). Every iterate stays in \(\mathrm{range}(\Theta^{\top})\), so the refined solution converges on the min-norm least-squares solution rather than on the ridge-biased one; the source records the worst-case recovery error falling from roughly \(7\times10^{-7}\) under the bare ridge to about \(10^{-15}\) with refinement (driversDecomp.ts:14–16). Finally the recovered shocks are mapped back through the column scaling, \(\hat\varepsilon_j = \hat\varepsilon_{N,j} / \lVert\Theta_{\cdot j}\rVert\).

    Why the columns are normalised¶

    Scaling every column to unit response norm before the solve imposes an equal-response-energy prior across shocks. Without it the \(\ell^2\) penalty quietly prefers whichever shock moves the observables most per unit of \(\varepsilon\), and prices the others out of their own attribution.

    The magnitudes involved are not subtle. Measured from the shipped US_SW07/SW.json, the stacked three-observable \(H = 12\) response norms are 1.28 for the monetary shock interest_, 2.12 for fiscal_, 4.21 for eqs, 4.50 for eb, 4.93 for ea, 11.58 for the wage markup ew and 13.84 for the price markup epinf. Roughly an order of magnitude separates the monetary shock from the markup shocks, and under a raw min-norm solve the monetary shock loses attribution to them for no economic reason.

    In identified configurations the normalisation is a pure reparameterisation: the licence fixtures (UK_SM11 at three observables, SW07 at seven observables with seven shocks) still recover to \(10^{-6}\) or better. In underdetermined configurations it removes the small-column bias — for SW07 at three observables, mean off-class leakage falls from 32% to 5% (class_recovery_results.txt). Its signature is visible in a constructed case: with two exactly collinear shocks whose response norms differ 2:1, the shipped solver splits the contribution equally where a raw min-norm solver would split it 4:1.

    Contributions, fit and residual¶

    Contributions are computed through the raw, unweighted \(\Theta\) and the un-normalised \(\hat\varepsilon\) (contributionsFromEps, driversDecomp.ts:198):

    \[ c_{k,o}(t) \;=\; \sum_{\tau \le t} \Theta[\,oH+t,\;kH+\tau\,]\,\hat\varepsilon_k(\tau), \qquad \hat z_o(t) = \sum_k c_{k,o}(t), \qquad u_o(t) = z_o(t) - \hat z_o(t). \]

    Because \(\Theta\hat\varepsilon \equiv \Theta_N\hat\varepsilon_N\) exactly, the column normalisation leaves the reported contributions unchanged; and because the row weights enter only the solve, they never touch the reported contributions either. The weights change which shock sequence is chosen, not how a chosen sequence is attributed.

    Rank and regime¶

    thetaRank (driversDecomp.ts:144) is a pivoted Cholesky on the smaller-side Gram matrix with a relative pivot tolerance of \(10^{-12}\) times the largest diagonal. The engine reports regime = 'exact-fit' when \(\mathrm{rank}(\Theta) \ge qH\) and 'residual-able' otherwise. The threshold is not delicate in practice: the two regimes on the shipped menu are about twenty orders of magnitude apart in conditioning, with full-rank models at \(\mathrm{cond}(\Theta) \lesssim 10^{2}\) and the rank-deficient CA_LS07 at \(\approx 3\times10^{17}\).

    Remark 1 (An exact-fit residual is zero by construction). In the exact-fit regime every path is reproducible, so the residual is identically zero and carries no information. It is not evidence that the named shocks explain the path. The residual becomes a genuine test only once the user watches more observables than the named shocks can span — that is, in the residual-able regime, where an unexplained dimension actually exists.

    The engine's entry point¶

    The whole decomposition runs through one call, displayed here in the form the code uses:

    decompose(irf, shocks, observables, H) → DriversDecomposition

    irf is a ModelIRFs record mapping each shock name to a record of response arrays keyed by model observable field. shocks is the string array of named shocks, length \(K\), in the order the columns are blocked. observables is an array of length \(q\); each entry carries key (the display key, for instance output or dc), irfField (the field to read from each shock's response record, usually the same string), path (the observable's scenario deviation path, length at least \(H\)), and an optional weight (the measurement-error row weight \(w = 1/\sqrt{1+\mathrm{me}}\), left undefined for the exact common three). H defaults to DRIVERS_H = 12.

    What comes back is a DriversDecomposition: eps, a Float64Array of length \(K\!\cdot\!H\) in shock-major order; contributions, a \(K \times q \times H\) nested array; fitted and residual and z, each \(q \times H\); the scalars lambda, rank and rows (\(= qH\)); and regime, either 'exact-fit' or 'residual-able'. The call throws when no shock is named, when a supplied path is shorter than \(H\), and — the budget rule, below — when more shocks are named than observables are watched.

    Unit conventions¶

    Every mapping in this section was measured from the shipped files and is regression-guarded by the test suite. None of it is assumed.

    From the BVAR panel to the three common observables¶

    The input is the active scenario's level deviation from baseline, indexed [t][j], in the smoother's level space: \(100\cdot\log\) for log variables, native units for linear ones. The long-run drift translates baseline and scenario rigidly, so it cancels in the deviation by construction (useStore.ts:11–16). commonObservablePaths (driversDecomp.ts:392) then builds the three MMB common observables:

    Model observable Built from the BVAR panel as US column
    output GDP level deviation (\(100\cdot\log\)), identity GDPH
    inflationq \(4\,(p_t - p_{t-1})\) of the price-level deviation, with \(p_{-1} = 0\) JGDP
    interest policy-rate deviation, annualised, identity — no division by 4 POLRATE

    The two factors of four are not conventions chosen here; they are read off the model file, which carries both the MMB common block and SW07's native observables. A regression test checks, on every shock and every horizon with a non-trivial response, that inflationq/pinfobs and interest/robs both equal 4.000 to better than \(10^{-9}\).

    Native observables (US bloc only)¶

    Two models expose real-side observables beyond the common three, and both maps were measured from the shipped response files rather than taken from the model papers.

    For US_SW07 (SW07_NATIVE_MAP) the four addable observables are consumption growth dc, investment growth dinve, real-wage growth dw from \(\Delta\)((LXBC − JGDP) deviation), and hours labobs from the LANAGRA deviation in level. All differences use \(\text{deviation}_{-1} = 0\).

    Two of those rows were corrected in August 2026 after an audit against the harmonised observable dictionary of the MMB real-time forecasting platform, which records the exact source construction of every model observable and ships the constructed observables as numbers. That turns a mapping from something argued into something measured: build the candidate from the GMAPS panel, line it up against the platform's own series, and read the fit. The benchmark is the revision floor — the row dy, where both sides are the identical formula on the identical series, and which therefore scores rmse 0.099 pp per quarter from data-vintage differences alone. A row at that floor is exact.

    row was measured now measured
    dc \(\Delta\)(CH) corr 0.837, rmse 0.308 \(\Delta\)(CH + JC − JGDP) corr 0.982, rmse 0.109
    dinve \(\Delta\)(FNH) corr 0.881, rmse 0.956 \(0.2384\,\Delta\)FRH \(+\ 0.7616\,\Delta\)FNH corr 0.984, rmse 0.351

    CH is chain-weighted real consumption deflated by its own price index, whereas the model observable is nominal consumption deflated by the GDP deflator; swapping the deflator is an identity, and same-vintage it reproduces the platform's series exactly. FNH is the nonresidential component alone, while the model observable is total private fixed investment — roughly a quarter of the series was absent, and it is the quarter that moves in housing and credit scenarios. FNH and FRH share the JGDP deflator, so their level sum is exactly the model's observable; but the log of a sum is non-linear and would break the additivity of §"Contributions", so the shipped row is its first-order share-weighted expansion at the measured residential share 0.2384. Linearising costs rmse 0.048 pp per quarter against the exact sum, 2.7% of the observable's own standard deviation, measured on the shipped US panel. The weights must not be re-tuned to a scenario origin, and a naive 0.5/0.5 average is worse than leaving the row unfixed.

    labobs is a proxy, and it is the one row that cannot be built correctly

    The model observable is hours per capita. LANAGRA is an establishment-survey employment headcount, and the US bloc carries neither an average-hours series nor population, so the intensive margin — hours per worker — is absent. Measured in the 12-quarter deviation space this panel works in, the proxy scores median correlation 0.906 against the true series with an error at the 12-quarter horizon of roughly 0.6 of the signal. A scenario that moves hours per worker without moving headcount is under-read.

    Two numbers circulate for this row and they measure different things. A historical shock decomposition rates it far lower, at 0.699 across seven observables — but that exercise is in levels, where the missing population trend dominates. A scenario deviation carries the same demographics in baseline and scenario, so the trend cancels exactly and only the intensive margin is lost. Quote 0.906 for this panel and 0.699 for a historical decomposition.

    A satellite bridge — projecting average hours onto columns the bloc already carries — was tested and rejected. In-sample it looks good (\(R^2\) 0.52, deviation correlation 0.906 → 0.940), but split at the financial crisis three of its five coefficients flip sign, and fitting pre-2008 to predict post-2010 gives \(R^2\) 0.305 against 0.523 in-sample. A within-window fit has no place in a mapping layer whose other rows are identities. The only real fix is adding average hours and population to the bloc, which requires re-estimating it.

    For US_CMR14 (CMR14_NATIVE_MAP, driversDecomp.ts:489) the BVAR-side construction is identical, again all factor 1, and the units were pinned by fitting the model's own observation equations. The anchor is gdp_obs \(= \Delta\)output exactly for every non-trend shock, which fixes gdp_obs in percent quarterly log growth, the SW07 dy convention. The three growth observables then fit as consumption_obs \(= 0.6366\,\Delta c + 1.0\,\texttt{log\_muzstar}\), investment_obs \(= 1.2526\,\Delta i + 1.0\,\texttt{log\_muzstar}\) and wage_obs \(= 0.5647\,\Delta\tilde w + 1.0\,\texttt{log\_muzstar}\), each to within \(7\times10^{-14}\). Every one of them carries exactly the same 1.0 trend loading that the percent-anchored gdp_obs does, which is what places them in the same percent-quarterly-growth units; the \(\Delta\)-term factors are internal model-variable scalings and are irrelevant to the data side. wage_obs is the real wage — the two-term fit is exact with no separate inflation loading, and a price-markup shock raises inflation_obs while wage_obs falls. Hours are hours_obs \(= 0.01\,\texttt{lhours}\) exactly, the same 0.01 that links the percent common column to its level counterpart, so hours_obs is a percent level deviation and takes the labobs convention at factor 1.

    CMR14's financial observables (credit_obs, networth_obs, premium_obs, Spread1_obs, pinvest_obs, RealRe_obs) are not mapped in this pass. There are no financial observables in the Drivers feature.

    Availability¶

    The native mode needs the spec columns CH, JC, JGDP, FRH, FNH, LXBC and LANAGRA — seven since the dc and dinve corrections, which draw on JC and FRH respectively. Only the US bloc ships them all. On every other bloc the drawer runs at three observables, the naming budget is three, and the class view is unavailable.

    A row assembled from several columns is withheld entirely if any one of them is missing, rather than being built from those present: a partial combination is a different series, not an approximation of the intended one.

    From observables to the main panel's display space¶

    Contributions are drawn in the units of the panel the user is already reading. Each observable maps into display space through a linear operator, either a gain \(s\,v_t\) or a scaled first difference \(s\,(v_t - v_{t-1})\) with \(v_{-1} = 0\) (obsDisplaySpec and toDisplayDev, driversDecomp.ts:608–643):

    Observable Operator Display unit
    output difference, scale 4 % q/q ann.
    inflationq gain, scale 1 (already \(4\Delta p\)) % q/q ann.
    interest gain, scale 1 %
    native difference-kind (dc, dinve, dw, consumption_obs, investment_obs, wage_obs) gain, scale 4 % q/q ann.
    native level-kind (labobs, hours_obs) difference, scale 4 % q/q ann.

    Because the operator is linear, contributions and residual transform additively, so the stacked bars plus the residual plus the baseline reproduce the scenario line exactly. That identity is pinned to \(10^{-8}\) in the test suite, for per-shock bars and for aggregated class bars alike. Note that dw and wage_obs subtract the deflator column, so the displayed series is compensation growth minus deflator growth.

    The two licensed rules¶

    The validation bench states, in its own verdict block (simple_decomp_results.txt:19–20), the rules it licenses: "name at most as many shocks as observables watched; added observables (with ME) raise the budget; collinear shock pairs are flagged." Both are enforced in the shipped tool.

    Rule 1 — the naming budget¶

    At \(q\) watched observables the user may name at most \(q\) shocks. The engine throws when \(K > q\) (driversDecomp.ts:236), and the interface disables every un-named chip once the budget is reached (DriversDrawer.tsx:1131). The budget is 3 + addedObs.length where the native mapping is available and 3 otherwise (DriversDrawer.tsx:519).

    The rule comes from criterion (e) of the bench: SW07 at its native seven observables with all seven usable shocks is fully identified, rank 84/84, with noiseless recovery at \(3.6\times10^{-15}\) and 100% of contribution paths recovered at 1% noise.

    Not every observable raises the budget. SW07's dy, pinfobs and robs, and CMR14's gdp_obs, inflation_obs and Re_obs, are excluded from the addable list because each is an invertible linear transform of an already-watched locked observable: dy is the difference of the output path, pinfobs is inflationq/4, robs is interest/4, and on the CMR14 side Re_obs is a constant \(0.2529\) times interest across all shocks and horizons. Adding one would raise the naming budget by one while buying no new rank, so the identification the budget rule promises would be fictitious. This is pinned against the data rather than against a curated list: a test requires each of the four legitimate SW07 addables to buy exactly \(H = 12\) units of new rank, and each of the three excluded transforms to buy exactly zero, alone and all three together.

    Rule 2 — the collinearity flag¶

    Two shocks whose stacked response paths point in nearly the same direction cannot be told apart by the data being decomposed, however well-conditioned the system looks. The build step therefore computes \(\lvert\cos\rvert\) between every pair of unit-normalised stacked three-observable \(H = 12\) response paths, exactly as bench_simple_decomp.m:112–125 does, and ships every pair above 0.95 in the index (collinearThreshold). The drawer warns whenever both members of a flagged pair are named, quoting the measured \(\lvert\cos\rvert\) to two decimals.

    The one-click "Use all" selection is greedy in the model's fixed shock order and skips any shock that forms a flagged pair with one already picked (useAllShockSelection, driversDecomp.ts:562). Hand-picking a collinear pair remains possible under Customize, with the warning shown.

    The rationale is that near-collinear columns break same-model recovery through the validated engine. Concretely, the CMR14 trio e_sigma, e_gamma and e_zetai is mutually flagged (measured \(\lvert\cos\rvert\) of 0.998, 0.983 and 0.975); the shipped greedy seven-shock set, which keeps exactly one of them, recovers the generating sequence far inside the \(10^{-6}\) criterion the test suite pins it against, while freeing a budget slot for a second member can push the worst contribution-path error past that criterion by several orders of magnitude, depending on which member is added.

    Remark 2 (Read a flagged pair jointly). Where a pair is flagged, the split of contributions between its two members is not identified — the solver is choosing among observationally equivalent splits by a norm criterion, not by evidence. The sum over the pair is meaningful; the division inside it is not. Keeping only one member of a collinear group is what preserves recovery, which is what the greedy default does.

    The class-view licence¶

    Grouping shocks into Monetary, Demand and Supply is what makes a decomposition readable, and it is also where a model-conditional exercise is easiest to over-sell. The tool therefore treats the class view as licensed at one configuration and greyed everywhere else.

    What the bench ran¶

    bench_class_recovery.m ran five (model, observable-set) cells under two solvers, against two pre-stated criteria: (f1) the recovered class-total path correlates at least 0.95 with the true class-total path in at least 90% of active-class instances over 20 seeds; (f2) mean off-class leakage is at most 25%. Both must pass. The full results are committed in docs/paper/class_recovery_results.txt:

    Model \(q\) Solver (f1) corr ≥ 0.95 (f2) off-class leakage Verdict
    US_SW07 3 raw 52% fail 32% fail fail
    US_SW07 3 colnorm 50% fail 5% pass fail
    US_SW07 7 raw 100% pass 0% pass pass
    US_SW07 7 colnorm 100% pass 0% pass pass
    US_CMR14 3 raw 58% fail 34% fail fail
    US_CMR14 3 colnorm 45% fail 32% fail fail
    US_CMR14 7 raw 87% fail 8% pass fail
    US_CMR14 7 colnorm 78% fail 3% pass fail
    US_FRB22_mcap 3 raw 20% fail 62% fail fail
    US_FRB22_mcap 3 colnorm 37% fail 47% fail fail

    The shipped solver is the column-normalised one. Exactly one cell passes both gates under it: US_SW07 at the full extended seven-observable set, with a perfect diagonal attribution matrix — Monetary, Demand and Supply each recovered at 100% with 0% leakage.

    The bench held all three coordinates fixed in that cell. Its observable set is \(\{\)output, inflationq, interest, dc, dinve, dw, labobs\(\}\) (bench_class_recovery.m:35) and its shock set is \(K = 7\), every usable column of SW07's class map.

    What the shipped code permits¶

    classViewLicensed(model, observableKeys, namedShocks) → boolean

    model is the index key of the selected lens, observableKeys the string array of watched observables, and namedShocks the string array of named shocks. The predicate (driversDecomp.ts:694–702) returns true only when the model is US_SW07, the observable keys contain all seven of the bench's set, and the named shocks contain all seven of interest_, eb, fiscal_, eqs, ea, epinf, ew. The drawer additionally requires that a class map exist for the model. The third argument is required, not optional, so a caller who forgets it gets a compile error rather than a silently wider licence.

    As shipped, the set of configurations in which the code permits the class view and the set the bench licensed are the same set, on all three coordinates. The predicate is permissive only towards supersets — naming or watching more than the bench's seven still returns true — and neither is reachable through the interface, since SW07 exposes exactly seven usable shocks and exactly four addable observables.

    Remark 3 (The licence has three coordinates, and un-naming revokes it). It is tempting to describe the class view as licensed "for SW07 at seven observables". That is wrong, and it was the defect the verification pass closed. If the user drops one shock under Customize, the licensed Monetary/Demand/Supply labels would otherwise survive on a split the bench never ran: the missing shock's energy is redistributed across the classes that remain, which is precisely the quantity the off-class-leakage criterion measures. The licence is a property of (model, watched observables, named shocks) jointly, and the Classes toggle greys out the moment any one of the three moves.

    US_SW07 yes (7 members) yes, and only at 7 observables with all 7 shocks named textbook shock names
    US_CMR14 yes (9 members) no its own class map as an organising grouping of families
    US_FRB22 yes (54 members, via alias) no empirical collinearity clusters
    US_FRB22_var yes (54 members, via alias) no empirical collinearity clusters
    US_FRB22_mcap yes (54 members) no menu-hidden; kept for the licence fixtures
    US_FRB08 no no one series per named shock
    EA_SW03, EA_SWW14 no no one series per named shock
    CA_LS07, HK_FP13, BRA_SAMBA08, UK_SM11 no no one series per named shock

    Because only the US bloc carries the five spec columns the native observables need, the licensed configuration is reachable on the US bloc only. Everywhere else the drawer runs at three observables and the Classes toggle is greyed, with the tooltip naming the reason and the results file.

    The class maps themselves live in pipeline/_shockbench/class_maps.json and are copied verbatim into the shipped index at build time, so they are amended there and not in the app. SW07's map assigns interest_ to Monetary; eb, fiscal_ and eqs to Demand; and ea, epinf and ew to Supply. CMR14's adds a Financial class (e_sigma, e_gamma). The FRB/US map covers all 54 shocks by a rule on the equation each _aerr residual attaches to — 1 Monetary, 16 Demand, 20 Supply, 14 Financial and 3 Other — which is a mechanical assignment, not an economic judgement about the shock.

    Remark 4 (CMR14's families are a grouping, not a licensed class split). For US_CMR14 the Groups view renders that model's own class map as "Monetary family", "Demand family", "Supply family" and "Financial family". This is an organising device for nine shocks, not a class decomposition with a licence behind it: the bench recovers those class totals in 78% of test instances against its 90% bar, at 3% off-class leakage. The drawer shows that number verbatim wherever the families appear, and any document describing them should do the same.

    The model menu¶

    The index ships twelve lenses. K is the number of usable shocks — those with all three common observables present and a stacked \(H = 12\) response norm of at least \(10^{-9}\) — and the rank and regime shown are for the default three-observable configuration.

    CA_LS07 is residual-able for a substantive reason: two of its three usable shocks are near-duplicates in the three common observables, so its response columns span only 24 of the 36 stacked rows however many of them are named.     The menu is grouped by relevance to the bloc on screen (DriversDrawer.tsx:137–148): "Own country" first (US to the five US lenses, EA to SW03 and SWW14, CA to LS07, HK to FP13, BR to SAMBA08, UK to SM11), then "Reference" (the US SW07/CMR14 pair where they are not already own-country), then "Other". The choice is remembered per bloc in localStorage under gmaps-drivers-model:<bloc>.

    The FRB/US census lenses¶

    The two 54-shock FRB/US lenses are handled differently from every other model, for two independent reasons. First, the class view is refused for FRB/US by the bench at the only observable set it can run at: at three observables both solvers fail both gates. There is no seven-observable FRB/US configuration, because the native observable mapping exists only for SW07 and CMR14. Second, the individual _aerr equation-residual shocks are not separable in the three common observables in the first place: 109 of the 1,431 shock pairs exceed \(\lvert\cos\rvert = 0.95\) for US_FRB22, and 117 for the VAR-expectations variant. The drawer therefore groups by the structure the response space actually has, rather than by the economics of the equations.

    Clusters are connected components of the \(\lvert\cos\rvert > 0.95\) graph, formed by union-find over the shipped pair list (build_drivers_index.mjs:124, mirrored app-side by connectedComponents, driversDecomp.ts:746). Each cluster is labelled by its largest member's equation name — largest stacked three-observable \(H = 12\) response norm, equation being the mnemonic minus the _aerr suffix — and clusters are ordered by size descending, then id ascending. US_FRB22 partitions its 54 shocks into 23 clusters, the largest being hqlfpr with 17 members (the financial/housing blob, which contains fiscal_, so the fiscal shock is not separately nameable in cluster mode), eco_l with 10 (the spending block) and lww_l with 4 (wages, labour force, ECI), followed by three pairs and 17 singletons — among them interest_. US_FRB22_var partitions into 21 clusters, with hqlfpr at 18, eco_l at 10, lww_l at 4, trci at 3, two pairs and 15 singletons.

    Remark 5 (Cluster members are chained, not mutually parallel). Collinearity is not transitive. A connected component of the \(\lvert\cos\rvert > 0.95\) graph links its members through a chain of pairwise-collinear edges, so two members of the same cluster can sit well below the threshold against each other. A cluster is therefore not a bundle of near-identical shocks, and the composite column used to represent it is a genuine first principal component of the member set rather than a proxy for an already-parallel bundle. The drawer says this in three places, and it is the wording to mirror.

    Naming a cluster names exactly one column. clusterCompositeIRF (driversDecomp.ts:780) builds the first principal component of the members' unit-normalised stacked three-observable \(H = 12\) paths, by 200 power iterations seeded from the largest-norm member, unit-normalised, with the sign fixed by a positive projection on that member. The budget therefore counts clusters, not members: three clusters at three observables, whatever their membership.

    Most cluster triples are not usable, and rank does not tell the user which. pickDefaultNamed (build_drivers_index.mjs:363) scans every possible triple through the shipped solver over 20 sparse truth seeds (a deterministic generator, seed 20260806) against the \(10^{-6}\) criterion. Of 1,771 possible triples for US_FRB22, 123 pass; of 1,330 for US_FRB22_var, 122. The builder then picks deterministically among the passers, maximising total member coverage, preferring a triple that contains the interest_ cluster, and breaking ties by shipped cluster order. That yields [hqlfpr, interest_, pcer_l] for US_FRB22, covering 19 of 54 shocks at a measured worst recovery error of \(2.5\times10^{-9}\), and [eco_l, interest_, ki_l] for US_FRB22_var, covering 12 of 54 at \(1.3\times10^{-7}\) — passing, but only an order of magnitude inside the criterion. The drawer warns whenever the user departs from the shipped default naming, because a full-rank \(\Theta\) is not evidence that a triple is usable: the top-three-by-size triple hqlfpr/eco_l/lww_l is full-rank and still fails the recovery criterion by orders of magnitude.

    Under Customize there is an "Experimental: raw shocks" fold that decomposes individual _aerr shocks instead of clusters. The chip list is the greedy non-collinear selection: 26 of 54 for US_FRB22 and 25 of 54 for US_FRB22_var. The budget still binds, so at three observables only three of them can be named.

    Working with the drawer¶

    The Drivers button, carrying an amber exp badge, sits in the scenario-action cluster of the chart grid (ChartGrid.tsx:3868) and appears only once there is something to decompose — that is, when any displayed, isolated or coupled scenario deviation, or an active external-forecast combination, has an entry exceeding \(10^{-9}\) in absolute value. The drawer is a fixed right-side overlay 480 px wide, closed by its × or by Escape, and it does not solve while closed.

    Example 1 (Reading a US scenario through the SW07 lens, default settings). We open Drivers on the US bloc with a scenario already displayed and change nothing. The drawer selects US_SW07, watches all seven observables — the three locked common ones plus Consumption (Δ), Investment (Δ), Real wage (Δ) and Hours (level) — and names all seven usable shocks. Because that is exactly the licensed configuration, the [Classes | Groups] toggle sits on Classes and the chart shows three stacked series, Monetary, Demand and Supply, plus a grey Residual, drawn as contribution bars anchored on the baseline path with the scenario line on top. The observable shown is Output, in % q/q ann.; a horizontal 100% shares strip sits underneath. The regime banner reads rank 84/84, exact-fit, so no residual, collinearity or rank warning fires, and the residual band is flat at zero (Remark 1). To read the same decomposition for inflation instead we change the "Contributions to" dropdown; the solve does not change, because it uses all seven observables jointly and only the display picks one.

    Example 2 (Decomposing on a bloc without the native columns). We switch the app to a non-US bloc and open Drivers. The lens is still US_SW07, but the five spec columns the native observables need are absent, so the budget is three and the named set is the greedy non-collinear three: interest_, fiscal_, ea. Classes is greyed with its tooltip, the view falls back to Groups, and the chart shows three per-shock series labelled Monetary (interest_), Government (fiscal_) and TFP (ea). The regime is 36/36, exact-fit. The caveat paragraph at the foot of the drawer gains the sentence explaining why Classes is unavailable. This is the honest reading available on that bloc: three shocks through a US lens, with no class aggregation behind it.

    Example 3 (The FRB/US census lens and its cluster naming). We select "FRB/US linearised (2022, MMB) — 54-shock census" from the model picker. The drawer fetches a further 10.7 MB of impulse responses, then names the shipped default triple hqlfpr, interest_, pcer_l, which covers 19 of the 54 shocks. Groups shows one series per cluster, labelled by each cluster's largest member. We open the "Cluster membership" expander to see which shocks each composite column stands for, and read the bottom caveat, which states that this lens has no row in bench_simple_decomp.m and that the clusters are empirical, chained collinearity components rather than economic classes. If we then re-name the clusters by hand, an amber warning appears: only the shipped default naming carries a build-time recovery check, and most alternative triples fail it even though the rank test passes.

    The controls fall into two groups. Always visible are the lens row (model title, any dropped-shock note, and a "Change model" link), the [Classes | Groups] toggle, the chart-view dropdown (Forecast, or Deviation from baseline), Reset, and Customize. Under Customize the drawer exposes:

    • Use all — watch every mappable observable, then name every unit the budget allows, skipping collinear duplicates.
    • Input source — "Scenario (displayed)" or "External forecast combination"; the latter is disabled and annotated when imports exist but the master switch is off, or when nothing is imported for this bloc.
    • Domestic | Global path — shown only for the scenario source, and only when both an isolated and a coupled path exist.
    • Observables — three locked chips with a padlock, plus the four addable native chips on the US bloc, each annotated with the fact that it raises the budget by one.
    • Measurement error — a strict-to-permissive slider shown only when native observables are added, displaying the current row weight \(w = 1/\sqrt{1+\mathrm{me}}\) with \(\mathrm{me} \in [0,4]\) and a default of 1.
    • Cluster chips — the cluster list for the two FRB/US lenses.
    • Experimental: raw shocks — a fold containing the raw/cluster switch and the raw shock chips.

    Reset restores US_SW07 with its Use-all default, Classes, the scenario source and the follow-display chart view, and it overwrites the saved per-bloc model choice.

    Remark 6 (The measurement-error slider does nothing at budget-max). At \(K = q\) the stacked system is square, so scaling both \(\Theta\) and \(z\) by a positive diagonal row weighting leaves the solution identical: \(W\Theta x = Wz \iff \Theta x = z\). In the default US configuration the slider is therefore rendered but disabled, and its tooltip says so and tells the user to un-name a shock if they want the added observables to have a role in the solve. The slider is real only in the underdetermined case.

    Remark 7 (The delta view need not match the panel's units). The chart view auto-follows the main display: when the app is showing deviations from baseline the drawer opens in "Deviation from baseline", otherwise in "Forecast", and a manual choice then sticks. The delta chart's bars are always the panel's rate deviation, whereas the main panels' "% vs base" mode has a level sub-mode and defaults to level. Auto-follow can therefore put the drawer in different units from the panel that prompted it. The axis title always states the unit; read it before comparing magnitudes.

    Remark 8 (The shares strip is a norm share, not a variance decomposition). For the selected observable, each series' share is the \(\ell^2\) norm of its contribution path divided by the sum of those norms plus the residual's, in percent. Shares therefore always sum to 100 and are never negative, which means the strip cannot display two contributions that offset each other as such. It is a magnitude summary, not a decomposition of forecast-error variance.

    Warnings fire for the residual-able regime (with rank and rows shown), for named shocks that form a flagged collinear pair (with the measured \(\lvert\cos\rvert\)), for decomposing a path other than the one displayed (the Domestic/Global override is sticky, so this warning shows outside the collapsed fold), for the experimental raw-shock mode, for rank-deficient named columns, and for departing from the validated default naming on the FRB/US lenses. An index fetch failure is reported as an error; a per-model response-file failure is recorded and offers a Retry, which matters for the two ~10.7 MB FRB/US files.

    The data payload¶

    The feature adds app/public/data/dsge/census/, containing the 36 KB index and eight census response files: CA_LS07 (47 KB), BRA_SAMBA08 (123 KB), EA_SW03 (200 KB), EA_SWW14 (217 KB), HK_FP13 (218 KB), UK_SM11 (231 KB), and the two FRB/US census files at 10.6 MB and 10.8 MB. Four further models are indexed rather than copied, since they already live in the irfs tree: US_SW07 (215 KB), US_CMR14 (1.8 MB), US_FRB08 (352 KB) and US_FRB22_mcap (407 KB). The SW07 and CMR14 files were regenerated by this feature to carry their full native shock sets; the interest_ and fiscal_ columns that the existing policy-counterfactual feature reads are unchanged to about \(5\times10^{-11}\) by that regeneration, which is re-export rounding.

    The index is fetched once per session on the first drawer open, and a model's response file on selection, cached per model for the session. Both go through loadJSON, a plain fetch under ${NEXT_PUBLIC_BASE_PATH}/data/ with no client-side decompression. In practice the default lens costs 36 KB plus 215 KB; choosing either 54-shock FRB/US lens costs a further 10.7 MB.

    The index carries schema: "gmaps-drivers-index/1", the build date, horizonQuarters (12, asserted equal to DRIVERS_H by the test suite), commonObservables, collinearThreshold (0.95), the verbatim shockClasses block, and one record per model. Each model record gives the site-absolute file path the drawer fetches and the repository source it came from; sha256 and sha256Source, which the test suite re-hashes against every shipped file; the usable shocks and the dropped list with a reason (zero-response or missing-observable); hasOutput; the collinearPairs with \(\cos\) rounded to six decimals; and, where applicable, an optional display title, sourceNote, menuHidden, classMapKey, clusters and defaultNamed. The full field list is in Data Schemas; the loader's types are at app/src/lib/data/loader.ts:96–160.

    Limits of the claim¶

    The feature is experimental, and it is badged as such in the interface. Its claim is model-conditional: the decomposition answers what mix of model \(M\)'s structural shocks would have produced the displayed path. It does not say what caused the scenario, and it is not model-free shock labelling. An earlier attempt at a model-free validation failed its pre-committed gate; those numbers are unlicensed, are not part of this feature, and appear nowhere in the tool or its documentation.

    What is validated is same-model recovery. Every number in simple_decomp_results.txt and class_recovery_results.txt comes from generating a path with a model's own known shock sequence and recovering it under that same model, so it measures the estimator, not the model, and not the world. A different lens gives a different answer, and the lenses are not equally validated. bench_simple_decomp.m ran exactly eight models — US_SW07, US_CMR14, EA_SW03, EA_SWW14, CA_LS07, HK_FP13, BRA_SAMBA08 and UK_SM11 — and never ran any FRB/US lens. The drawer's bottom caveat is therefore per-model: it cites the bench only for those eight, and for the others states that what backs the shipped default naming is a build-time recovery check rather than a bench row. That build-time scan exists for the two clustered FRB/US lenses. US_FRB08 has neither a bench row nor a build-time scan, and no document should assert one for it.

    Aggregation into classes is the narrowest claim on the page, and it is licensed at one configuration only: US_SW07, all seven observables watched, all seven class-map shocks named. Un-naming a single shock revokes it (Remark 3). CMR14's families are that model's own class map used as an organising grouping and not a licensed class split (Remark 4), and the FRB/US clusters are an empirical grouping of response directions whose members are chained rather than mutually parallel (Remark 5). Of those clusters, only the shipped default naming carries a recovery check, and that check is a build-time scan rather than a bench: 123 of 1,771 possible triples pass for US_FRB22 and 122 of 1,330 for the VAR-expectations variant. Any other naming is exploratory. A full-rank \(\Theta\) is not evidence to the contrary, because conditioning is what decides whether a naming is usable and rank does not imply it.

    Four smaller limits are worth carrying into any write-up. Where a pair of shocks is flagged collinear, the split within that pair is not identified and the pair must be read as one object (Remark 2). In the exact-fit regime the residual is zero by construction and is no evidence that the named shocks explain the path (Remark 1). The shares strip below the chart is a norm share and not a variance decomposition, so it cannot show two contributions offsetting each other (Remark 8). And the seven-observable mode exists only on the US bloc; every other bloc runs at three observables, where no configuration in the menu licenses a class view.

    Finally, three numbers quoted in source comments do not reproduce under independent measurement and are deliberately absent from this page: a pair of SW07 column norms, an error range for a CMR14 collinear pair, and a failure magnitude for the FRB22 top-three-by-size triple. In each case the qualitative point holds and is stated above; the specific figure is not repeated.

    Regeneration¶

    Example 4 (Rebuilding the shipped index and re-running the validation benches). We regenerate the index whenever the class maps, the census responses or the model menu change. The builder reads pipeline/census_irfs/MANIFEST.json, each census model's Taylor.json, the class maps, and the four irfs-tree response files; it writes the index and copies each census file into the public tree, refusing to ship any file whose sha256 does not match the manifest. We then re-run the two MATLAB benches, which print to stdout rather than writing files, so the committed transcripts under docs/paper/ are captured by redirection. Finally we run the licence tests, of which there are 26 across the three Drivers test files. The commands are as follows:

    # 1. Rebuild the shipped index and the census copies (runs from anywhere in the repo).
node app/scripts/build_drivers_index.mjs

# 2. Re-run the two validation benches and capture their transcripts.
matlab -batch "run('pipeline/bench_simple_decomp.m')"  > docs/paper/simple_decomp_results.txt
matlab -batch "run('pipeline/bench_class_recovery.m')" > docs/paper/class_recovery_results.txt

# 3. Re-run the licence tests (26 across drivers-decomp{,-v2,-v3}.test.ts).
cd app && npm test

    Two prerequisites are worth stating before anyone runs step 1 or step 2. The builder needs pipeline/census_irfs/, the 97-model census response tree, which is not present on the deployment branch; without it the script fails at its first read. bench_simple_decomp.m reads the shipped US_SW07 and US_CMR14 files plus the six census models' Taylor.json, and bench_class_recovery.m reads the class maps, those same two shipped files and US_FRB22_mcap/Taylor.json, so both benches run only in a checkout that carries the census tree. The public census/*.json copies are byte-identical to their sources by the sha gate, but both scripts hard-code the pipeline/census_irfs paths, so pointing them at the public copies is a code edit rather than a command-line option.

    Placement in one line¶

    A model-conditional reading of a scenario path: the tool solves for the sequence of a chosen MMB model's own structural shocks that reproduces the displayed path over twelve quarters, draws the contributions in the panel's units with an explicit residual, and gates every interpretive step — the naming budget, the collinearity flag, the class-view licence — on what the same-model recovery benches actually validated. It is the structural-interpretation counterpart to the accounting satellites: where the fiscal and external blocks derive stocks from the BVAR path by identity, this one reads that path through a model's lens, and it claims no more than the lens.
