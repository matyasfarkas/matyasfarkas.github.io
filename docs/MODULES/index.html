    Module & API Reference¶

    A per-module reference for the browser-side compute engine in app/src/lib/compute/* and the JSON data loaders in app/src/lib/data/*. Since 4.0.0 every data file reaches these modules through the data pack (data/dataManifest.ts): the data and the estimated model are separate from the tool, and the dates come from the pack, not from the code. Each section lists the module's responsibility, its key exported signatures with input/output shapes, the numerical thresholds and unit conventions that matter, and where it is called.

    This page is a navigable reference, not a tutorial. For the architecture overview, the per-bloc file contract, and the estimation pipeline see:

    • Architecture for AI — end-to-end data flow and the 8-file bloc contract
    • Adding a country and Re-estimating models
    • Fiscal block methodology — the budget-identity recursion in detail
    • Data contracts & JSON schemas — the 8 per-bloc JSON files, including the spec.json prior / transformation / isFinancial tags this engine reads
    • Pipeline — the MATLAB GVAR-EM estimator and Python data builders that produce the artifacts the modules below consume

    The two estimation-side facts that the browser engine inherits and must be read alongside the module reference:

    • Per-variable prior tag. Each spec.json variable carries prior ∈ {"RW","WN"}. RW (random walk) is the default own-first-lag prior mean of 1; WN (white-noise / stationary) sets the own-first-lag prior mean to 0 so the series mean-reverts. This is a property of the MATLAB estimator (bvarGLPmf.m, §Fiscal stationary prior), not the TS engine, but it changes the shape of the baselines the engine loads — the fiscal GDP-ratios (FREV_GDP, FPEXP_GDP, SFA) revert to their in-sample mean instead of drifting at the long horizon, and in the deployed growth-rate model so do the growth rates of real GDP and prices (those columns are estimated in first differences and also tagged WN). See DATA_SCHEMA §3 for the field and PIPELINE §5 for how it is set.
    • isFinancial and COVID masking. A variable with isFinancial:true is kept observed through the 2020Q2–Q4 COVID-as-missing window (only macro columns + the two macro stars are masked). The global commons GLB_USEQ (US equity) and GLB_OIL (oil) are isFinancial:true everywhere, so they condition the imputation rather than being imputed.

    All matrices in this engine are flat row-major Float64Arrays wrapped as { data, rows, cols } (see matrix.ts). All BVAR data is in companion space: 100·log levels for log variables, the raw value/rate for lin variables. A quarter-on-quarter annualized growth rate is 4·Δ(level) for a log variable.

    Fiscal stationary prior¶

    Where it lives. BVAR/MFBVAR/GLPreplicationWeb/bvarGLPmf.m (the GLP/Minnesota prior builder), threaded through BVAR/MFBVAR/cgl_bvarV5.m (the COVID-as-missing data-augmentation Gibbs), driven by the estimators pipeline/export_bvar_gvar24_loop.m (GVAR) and pipeline/export_bvar_euro_redesign.m (the 17 euro members; the older export_bvar_euro_fsap.m uses the same rule).

    The problem it fixes. Under the default random-walk own-lag prior (mean 1) the fiscal GDP-ratios FREV_GDP, FPEXP_GDP, SFA inherit a near-unit-root and drift at the long horizon — e.g. US revenue stuck near the last-observed ~19% of GDP rather than reverting toward its in-sample ~17.4% mean. A GDP-ratio is economically stationary, so a random-walk prior is the wrong shrinkage target.

    The mechanism. GLP shrinks each equation's own-first-lag coefficient toward a per-variable prior mean held on the diagonal of the prior-mean matrix b. bvarGLPmf.m builds it from a vector diagb, and the pos argument zeroes the selected entries:

    % BVAR/MFBVAR/GLPreplicationWeb/bvarGLPmf.m  (lines 193–195)
diagb        = ones(n,1);
diagb(pos)   = 0;   % own-first-lag prior mean = 0 for the WN (stationary) variables in pos
b(2:n+1,:)   = diag(diagb);

    pos is the 3rd positional argument of cgl_bvarV5 (named stationary in its signature):

    % BVAR/MFBVAR/cgl_bvarV5.m
function [Xcond,storeP,BETA,SU,X_interp0,Dforecast] = cgl_bvarV5(x,p,stationary,nDraws,nBurn,MCMCconst,hz,varargin)
pos = stationary;                       % line 19
...
r = bvarGLPmf(xx(1:lastFull,:), p, ..., 'pos', pos);   % line 54

    How the estimators set pos. Each reads the per-variable prior string from the spec and selects the WN columns of the kept domestic block (stars are appended after the domestic columns and are always RW):

    % pipeline/export_bvar_gvar24_loop.m
statCols = find(Spec.Prior(keep)=="WN")';   % domestic WN columns; [] if the spec has none
...
[Xcond,~,B,S,~,Dfc] = cgl_bvarV5(x, lags, Dc.statCols, nDraws, nBurn, MCMCconst, H, ...);

    % pipeline/export_bvar_euro_fsap.m
Prior    = priorsfrom(J.variables);         % per-variable "RW"/"WN" string array, RW default
statCols = find(Prior=="WN")';
[~, storeP, BETA, SU, ~, Dforecast] = cgl_bvarV5(x, lags, statCols, nDraws, nBurn, MCMCconst, H, ARGS{:});

    priorsfrom is deliberately robust to MATLAB's jsondecode dropping a prior field that is present on only some variable objects (a heterogeneous struct array collapses the field); an absent field ⇒ all-RW (the historical behaviour).

    Which variables are WN. The three fiscal GDP-ratios, in all 41 fiscal economies. EFFI (the effective rate, isFinancial:true) stays RW — a rate level is not a mean-reverting ratio. In the deployed growth-rate model (BVAR_DIFF_GP=1, Oct 2026) real GDP, the headline price and DEFL_<CC> are estimated as growth rates and also carry WN (the US: GDPH, JGDP). The fiscal tags in the shipped US/spec.json:

    Variable transformation prior financial
    FREV_GDP (revenue/GDP) lin WN macro
    FPEXP_GDP (primary exp/GDP) lin WN macro
    SFA (stock-flow adj/GDP) lin WN macro
    EFFI (effective rate, % p.a.) lin RW financial

    Effect and scope. The fiscal ratios mean-revert to their in-sample means at the long end (at the time of the change: US revenue → ~17.4% instead of ~19%). The change was byte-identical (a no-op) for blocs without a fiscal block, whose statCols was empty. Committed in 6f0161a (prior change), 22250be / e38673a (the then 33-bloc refit + port). The browser engine reads the resulting mean-reverting baselines unchanged — there is no TS-side code for the prior.

    Coherence fixes (companion to the refit)¶

    Shipped alongside the fiscal-prior refit (22250be / e38673a); they change the content of the loaded JSON, not the engine:

    • GLB_USEQ and GLB_OIL are isFinancial:true everywhere. Both are now kept observed through the COVID-as-missing window (2020Q2–Q4) instead of being imputed as macro columns, so the US-equity and oil paths condition the imputation of the masked macro block. Verified in US/spec.json (GLB_USEQ → log·RW·fin, GLB_OIL → log·RW·fin).
    • Canada IP_CA rebuilt as a log-LEVEL. IP_CA carries transformation:"log" (a level the engine differences to a growth rate) rather than a pre-differenced series. Verified in CA/spec.json. (Then chained from the discontinued FRED level index; since the Oct 2026 rebuild, the OECD production index per pipeline/sources/registry/CA.json.)
    • Per-economy variable table. A transformation · prior · financial table was added to the user manual; all 1048 variables across the then 50 shipped specs were audited coherent.

    The shipped US/spec.json is the authority: FREV_GDP/FPEXP_GDP/SFA are WN, and GLB_OIL/GLB_USEQ are isFinancial:true (the example in DATA_SCHEMA §3 matches it).

    matrix.ts¶

    Responsibility. Core dense linear algebra over flat Float64Arrays, row-major. No external dependency. Every other compute module imports from here.

    Type¶

    interface Matrix { data: Float64Array; rows: number; cols: number }

    Key exports¶

    Function Signature Notes
    mat (rows, cols, values?: number[]) => Matrix row-major; values optional
    eye / zeros (n) => Matrix / (rows, cols) => Matrix identity / zero
    get / set (a, i, j) => number / (a, i, j, v) => void element access
    multiply (a, b) => Matrix skips zero entries of a (sparse-friendly)
    multiplyVec (a: Matrix, v: Float64Array) => Float64Array matrix·vector
    transpose, add, subtract, scale, symmetrize shape-preserving add/subtract throw on dimension mismatch

    solveMatrix (A, B: Matrix) => Matrix solves A·X = B column by column
    inverse (A) => Matrix solveMatrix(A, eye)
    cholesky (A) => Matrix lower-triangular L, A = L·Lᵀ; throws when a diagonal ≤ 1e-14 (not positive definite)
    toeplitzLower (irf: number[], horizons) => Matrix lower-triangular impulse-response convolution matrix for B&M

    Numerical thresholds. LU singularity pivot floor 1e-15; Cholesky positive-definite floor 1e-14. These are the two failure modes consumers must guard (the smoother and the simulation draw catch a failed Cholesky and fall back to a diagonal sqrt).

    kalman.ts¶

    Responsibility. Companion-form state-space construction and the Durbin–Koopman (DK) filter + smoother for conditional forecasting of a single BVAR bloc. Ported from MATLAB conforekf.m / VARcf_DKcks.m / runKF_DK.m. This is the affine engine the GVAR solver probes.

    State-space form (state a_t = [y_t; y_{t-1}; …; y_{t-p+1}], dimension n·p):

    a_t = T·a_{t-1} + c2 + u_t,   u_t ~ N(0, Q)
y_t = Z·a_t + c1 + e_t,        e_t ~ N(0, R)

    Core types¶

    interface BVARParams {
  betahat: Matrix; sigmahat: Matrix; n: number; lags: number
  seasonalRows?: number   // 0 (default/legacy) or 3 — quarterly seasonal-dummy rows in betahat
  qoyNext?: number        // quarter-of-year (1..4) of the FIRST forecast row (required if seasonalRows>0)
}
// betahat is (1 + nsr + n·lags, n) where nsr = seasonalRows (0 legacy): row 0 = constant,
//   rows 1..nsr = seasonal-dummy coefficients (γ_Q2/γ_Q3/γ_Q4 vs the Q1 base), the rest = lag coefficients
// sigmahat is (n, n) innovation covariance

interface LinObs { h: Float64Array; value: number }  // linear-combination pin: h'·y_t = value

    Key exports¶

    Function Signature (abbreviated) Output
    buildStateSpace (params: BVARParams) => StateSpace companion T, Z, Q, R, c1, c2; R = 1e-12·I (tiny measurement noise). Reads lag coefficients at row 1+nsr; for a seasonal bloc (nsr=3) also precomputes c2ByQ (4 quarter-specific transition constants) + stores qoyNext
    c2AtStep (ss: StateSpace, t: number) => Float64Array transition constant at forecast step t (seasonal-aware): picks c2ByQ[((qoyNext−1+t) mod 4)]; falls back to the static c2 when nsr=0
    initState (data: Matrix, lags) => { a0, P0 } last p rows stacked; P0 = 1e-7·I
    kalmanFilter (ss, Y, a0, P0, linObs?) => { filteredA, filteredP, predictedA, predictedP, innovations, ZF } forward pass; Y is (n, T_fwd), NaN = missing
    kalmanSmoother (ss, predictedA, predictedP, filteredA, innovations, ZF, Y, linObs?) => Matrix DK backward pass (n·p, T_fwd)
    conditionalForecast see below the production single-bloc forecast
    affineBlocKernels see below the ~10–20× GVAR perf path
    dkSimulationDraw (params, hist, condPaths) => { smoothed, forward } one DK simulation-smoother draw (band loop)
    bvarForecastDraw (params, hist, H, addInnovation=false) => Matrix iterated VAR forecast; addInnovation toggles parameter-only vs predictive bands

    conditionalForecast¶

    function conditionalForecast(
  params: BVARParams,
  historicalData: Matrix,                 // (T_hist, n), companion space
  condPaths: Matrix,                      // (H, n), NaN = free (to be forecast)
  linConstraints?: { t: number; h: Float64Array; value: number }[]
): { mean: Matrix; variance: Matrix[] }   // mean (H, n); variance is H × (n, n)

    Given history and a partially-observed future path, returns the smoothed forecast for all variables. Per-variable pins live in condPaths (set a cell, leave others NaN); the optional linConstraints pin a linear combination h'·y_t = value at quarter t (used for the fiscal primary-balance constraint revenue − primaryExp = target). The forecast is affine in the pinned values for a fixed pin mask — the property the GVAR solver exploits.

    Convention invariant. An all-NaN condPaths reproduces baseline_levels.mean to ~1e-11. This is the canary that the engine and the shipped data agree.

    ⚠️ The returned variance is the FILTERED state covariance, not the DK-smoothed one (it is submatrix(filteredP[t], …), kalman.ts:405). The MEAN is smoothed; the variance is not — so the conditional band is overstated for quarters that precede a future pin (a later observation would tighten them). Known issue #4.

    Called from useConditionalForecast.ts (single-bloc path), ChartGrid.tsx, gvarSolve.ts (baseline + every probe), and runGvarBandSolve.ts.

    affineBlocKernels¶

    function affineBlocKernels(
  params: BVARParams,
  historicalData: Matrix,
  condPaths: Matrix,    // (H, n) probe BASELINE: pin mask + baseline values
  cells: number[]       // variable columns to bump (one kernel set per column)
): { Sc: Matrix; kernels: Matrix[][] }
// Sc = baseline smoothed mean (H, n)
// kernels[ci][tp] = (H, n) smoothed-mean response to condPaths[tp, cells[ci]] += 1

    The exact perf path for the GVAR coupling build. Because conditionalForecast is affine in the pinned values for a fixed mask, the filter/smoother factors (PPred_t, gain PZF_t, smoother L_t, ZF_t) are value-independent. affineBlocKernels computes them once (one full filter+smoother pass on condPaths), then evaluates each unit-bump kernel as a cheap delta forward/backward recursion (pure matvecs). The arithmetic is byte-equal to running conditionalForecast once per (cell, tp) probe, at a large constant-factor win (~10–20×, measured on the then n=41, lags=3, H=20 endogenous US bloc; the deployed US bloc is n=40, lags=4). Used inside gvarSolve.ts's blocKernels.

    Seasonal dummies (seasonalRows / qoyNext / c2AtStep)¶

    NSA-seasonal blocs (in the deployed pack: 17 coupled blocs + all 17 euro members — see ARCHITECTURE_FOR_AI.md §5·EM.s; the manifest's blocs.<CC>.seasonalRows lists them) are estimated with three quarterly seasonal dummies D = [q==2, q==3, q==4] (Q1 base). The estimator therefore ships betahat with the layout [constant; γ_Q2; γ_Q3; γ_Q4; B_1; …; B_p] (k = 1 + nsr + n·lags, nsr = seasonalRows), plus seasonalRows in companion_mean.json and seasonalRows/qoyNext in spec.json. The engine handles this without a new code path:

    • buildStateSpace reads the lag coefficients at row 1 + nsr (skipping the deterministic dummy rows), and for nsr > 0 precomputes c2ByQ — the 4 quarter-specific transition constants (the Q1-base c2 = betahat[0] plus γ_Q2/γ_Q3/γ_Q4 on the top n rows) — and stores qoyNext on the StateSpace.
    • c2AtStep(ss, t) returns the constant for forecast step t via q = ((qoyNext−1+t) mod 4), so the filter/smoother prediction step and the forecast-draw recursion (bvarForecastDraw, which also applies the per-step dummy directly) get the right quarter's intercept. nsr = 0 ⇒ c2AtStep returns the static c2 and every path is byte-identical to the pre-seasonal engine.

    The seasonal-aware conditional forecast is thus the same conditionalForecast / affineBlocKernels call — only the transition constant varies by quarter. Consumers that build BVARParams and must thread { seasonalRows, qoyNext }: gvarSolve.buildParams / makeCountryModel, useConditionalForecast, runGvarBandSolve (per-draw), driftSetter, the ChartGrid band paths, and the pipeline .mjs scripts (member_extend, nowcast_complete, regen_gvar_bands, precompute_gvar_coupling, verify_gvar24, refresh-quarter).

    🔴 PHASE RULE. qoyNext is always recomputed from the app's own date grid via dates.qoyNextOf(country) (quarter after lastHistOf, wrapped 1..4; lastHistOf comes from the data-pack manifest); the shipped spec.json.qoyNext is on the estimation grid, which a within-year data shift moves — trusting it would mis-phase every seasonal constant. setPanelDates also checks the manifest's declared qoyNext against this value and stops the load on a mismatch. makeCountryModel sets params.qoyNext = qoyNextOverride ?? qoyNextOf(code) (the override is for the node pipeline scripts only). See DATA_SCHEMA.md §3.3.

    Constant Value Site Purpose
    Measurement noise R 1e-12·I buildStateSpace (set(R,i,i,1e-12)) near-exact observation; keeps the filter conditioned
    Initial state cov P0 1e-7·I initState / dkSimulationDraw tight diffuse prior on the seeded last-p rows

    These compose with matrix.ts's solve (singular pivot < 1e-15) and cholesky (PD diagonal ≤ 1e-14): a failed cholesky(Σ) in a simulation draw is caught and replaced by the diagonal square root above, so a marginally non-PD posterior Σ degrades gracefully rather than throwing.

    gvarSolve.ts¶

    Responsibility. The cross-country GVAR scenario solver. Each bloc is an independent single-country BVAR whose baseline is computed once; cross-country coupling enters only through the scenario delta, which propagates via three trade-weighted "RoW" star variables (plus, when the US is endogenous, the US global commons). Reuses kalman.ts unchanged.

    The delta system is a linear fixed point x = M·x + d (x = stacked star pin-deltas, optionally augmented with US-global deltas). It is solved two ways that agree to ~1e-6:

    1. Gauss-Seidel sweeps (solveGVAR) — sums the Neumann series Σ Mᵏ d.
    2. Direct closed form (solveGVARLinear / solveGVARClosedForm) — (I−M)⁻¹d or the inverse-free Neumann fixed point, with M cached across scenarios that share a pin structure.

    Star variables and link convention¶

    Each non-US (and endogenous-US) spec carries three block:'row' stars, all lin in the receiver:

    Star Meaning Linked partner series
    ROWDEM (DEM) trade-weighted foreign GDP growth, % q/q ann partner GDP (log)
    ROWINF (INF) trade-weighted foreign inflation, % q/q ann partner deflator/CPI (log)
    ROWFIN (FIN) trade-weighted foreign short rate, % partner policy rate (lin)

    gdp/price deltas are 4·Δ(level-gap) growth operators (t=0 anchored to the shared in-sample last level, whose delta is 0); rate deltas are the level gap. Rate-less blocs (CH, NO) drop out of FIN; hyperinflation blocs (AR) drop out of INF and FIN. (NOMINAL_GDP_BLOCS is empty since the 2026-06 CN-only re-estimate — CN now ships real GDP, so its DEM reads gdp directly rather than gdp − price.)

    US_ENDOGENOUS augmented state¶

    When the US is a coupled bloc it both receives partner spillovers (its own ROW*_US stars) and drives every RoW bloc's global commons (oil / US 10Y / US BAA / US equity), which RoW blocs pin to own-base + US-global-delta. The compact state is therefore augmented:

    x = [ star pin-deltas s_{c,v,t} for every coupled bloc c (US included) ]
    ++ [ US global-column deltas gΔ_{p,t} ]

    with three coupling families assembled in buildLinearSystemEndo: (1) star ← star, (2) US-global ← US-star (definition row), (3) RoW-star ← US-global. solveGVARClosedFormEndo solves x = (I−M)⁻¹d (cached inverse) or the inverse-free Neumann fixed point (maxIt = 2000, tolerance 1e-10), then reconstructs each bloc with one final conditionalForecast.

    ⚠️ Only a console-level ρ(M) < 1 divergence guard on the live solve (known issue #3). When the Neumann iteration does not converge, solveGVARClosedFormEndo computes ρ(M) and runGvarSolve treats ρ ≥ 1 as diverged: a console warning and no caching — but no on-screen warning. ρ is shipped in the artifact (0.971875 in the deployed pack). See Known issues #3.

    fiscalAccounting.ts¶

    Responsibility. Derives the public-finance reporting variables (primary/overall balance, deficit, interest, debt-to-GDP, gross financing needs, snowball) from the BVAR-estimated fiscal drivers via the IMF FPP / CBO budget identity. Debt is derived, never estimated. See fiscal block methodology.

    Units (the main bug source)¶

    Quantity Unit
    revenue, primaryExp, sfa, amortization, debt-service-to-GDP % of GDP, annual ratio
    effRate % per annum (effective rate on the debt stock)
    gNomQ % per quarter (nominal GDP growth)
    d0, debt debt-to-GDP, %

    The recursion (per quarter, lagged debt d₋₁) — LIVE / displayed path¶

    This is computeFiscalBlock (fiscalAccounting.ts:163), the only fiscal recursion wired to the displayed debt-to-GDP charts and bands (called from ChartGrid.tsx and runGvarBandSolve.ts). It is a passive accounting recursion — no debt-feedback term:

    pb_t      = rev_t − primexp_t                             // primary balance (NO Bohn term)
i_eff_t   = effRate_t                                     // effective rate (NO risk premium)
int_t     = i_eff_t · d₋₁ / 100                           // interest / debt service, % GDP
deficit_t = int_t − pb_t
d_t       = d₋₁·(1 + i_eff_t/400)/(1 + gNomQ_t/100) − pb_t/4 + sfa_t/4
gfn_t     = deficit_t + amortization_t

    All four drivers (rev, primexp, effRate, sfa) are BVAR-forecast; debt/GDP is a derived accounting identity, never a BVAR variable. sfa_t in the deployed roll is the structural constant sfaDefault (not the per-quarter forecast SFA column — that gets dragged to extremes by the long-run anchors). There is no debt→primary-balance reaction and no debt→yield risk premium in anything the user sees.

    ⚠️ The γ/β (Bohn fiscal reaction function [FRF] + risk-premium) levers are DORMANT / test-only. A separate function runFiscalRecursion (fiscalAccounting.ts:66) adds the optional terms pb_t += γ·(d₋₁ − d*) (Bohn, default 0.03) and i_eff_t += β·max(0, d₋₁ − d*) (risk premium, default 0), gated by feedbackOn. runFiscalRecursion has ZERO production callers — it is invoked only by __tests__/compute/fiscalAccounting.test.ts and fiscal-backcast.test.ts. No UI control sets γ/β/feedbackOn. They are documented and validated but not in the live path; a possible future endogenous-debt-feedback extension, not current behaviour. See fiscal-block-methodology.md.

    ✅ CN inflation double-count — RESOLVED (2026-06). computeFiscalBlock forms gNomQ as Δ(level[idx.gdp]) + Δ(level[idx.deflator]). The CN block previously shipped a nominal GDP_CN, so the price term was double-counted; the surgical CN-only re-estimate replaced it with real GDP, so CN's roll-forward now matches the other economies. (At the time a CN-only graft; CN's fiscal price column is CPI_CN.)

    Function Input → output

    Driver provenance — the stationary prior matters here¶

    The three estimated drivers computeFiscalBlock reads off the level path — revenue (FREV_GDP), primaryExp (FPEXP_GDP) and sfa (SFA) — are exactly the variables now carried with the stationary WN prior (§Fiscal stationary prior). So the level path this module differences and rolls forward now mean-reverts at the long end rather than drifting; the derived debt-to-GDP trajectory inherits that. effRate (EFFI) stays RW. The recursion code is unchanged — only the shape of the forecast it consumes changed.

    The two parametrisations (debt service vs effective rate)¶

    Both runFiscalRecursion and computeFiscalBlock branch on whether an estimated debt-service-to-GDP column is supplied:

    Supplied Interest intₜ (% of GDP) Effective rate (% p.a.)
    dsvc / idx.debtService set = dsvcₜ directly (the BVAR forecast) backed out: intₜ·100/d₋₁
    not set (fallback) = effRateₜ · d₋₁ / 100 = effRateₜ (the estimated EFFI)

    The quarterly roll-forward iQ = effRate/400 = intₜ/(4·d₋₁) is identical either way (this keeps the effRate-only callers byte-identical and fixes a ~100× over-statement of interest on the DSVC path).

    driftSetter.ts¶

    Responsibility. The live user-facing long-run-target ("Prior for the Long Run"-style) anchor. It does not re-estimate, re-solve the GVAR, or reweight draws: it shifts the companion constant by δC and translates the forecast by exactly ΔY_{T+h} = S_h·δC, where S_h = Σ_{k<h} T^k is the partial companion-power sum built once per bloc from the shipped companion and cached, so each slider change is a cheap mat-vec add. The same δC deviation is added identically to the central path and to every quantile, so the fan translates rigidly — band widths are invariant and quantiles cannot cross — while the terminal value hits the target exactly. This replaces the removed longRunTilt.ts entropic-tilt mechanism (KL-min importance reweighting of posterior draws), which needed a Compute and degenerated (ESS → 1) on a joint multi-target tilt.

    Per-variable vs joint, rigid vs transition¶

    Targets can be solved per-variable or jointly (AnchorMode = 'perVariable' | 'joint'); the production entry computeDriftDeltaFull solves multiple set targets jointly when the system is tame (else it falls back to the per-target δc). The adjustment shape is rigid or transition (AnchorShape, default transition — phased in along the variable's own estimated convergence profile so there is no origin jump; both shapes share the same exact terminal). The GVAR cross-bloc spillover of a local anchor lives in gvarDriftSpillover.ts.

    driversDecomp.ts — the Drivers decomposition engine (EXPERIMENTAL)¶

    Responsibility. Takes the deviation of a scenario path from its baseline and asks a chosen DSGE model from the Macroeconomic Model Base (MMB) which sequence of that model's own structural shocks would have produced it over the first twelve forecast quarters. It returns the per-shock contribution paths, the fitted path, and an explicit residual for the part the named shocks cannot reproduce. This is the "filter the path through the model" exercise familiar from NAWM-II practice, run on a path object rather than by inverting a recursion. Ported from the MATLAB benchmark pipeline/bench_simple_decomp.m, whose transcript is committed at docs/paper/simple_decomp_results.txt.

    What it does not do, stated up front. The feature is experimental and its claim is model-conditional: it reports the mix of model M's shocks that reproduces the path, not what caused the path, and it is not model-free shock labelling. Its validation is same-model recovery — generate a path from a model's own known shock sequence, decompose it under that same model, compare the recovered contribution paths with the truth — so the numbers speak to the estimator, not to the model and not to the world. A different lens gives a different answer, and the lenses are not equally validated: bench_simple_decomp.m ran eight models (US_SW07, US_CMR14, EA_SW03, EA_SWW14, CA_LS07, HK_FP13, BRA_SAMBA08, UK_SM11) and never touched an FRB/US lens. Aggregating shocks into economic classes is licensed at exactly one configuration and greyed everywhere else (Remark 3). The module has no financial observables, no bands, and no notion of posterior uncertainty: it is a deterministic map from one deviation path to one shock sequence.

    The question, and the object that answers it¶

    The decomposition answers: which sequence of model M's structural shocks, arriving over the forecast window, would have produced the path the app is displaying? Write H = 12 for the horizon (DRIVERS_H), q for the number of watched observables and K for the number of named shocks. The scenario deviation is carried into the model's observable space as z_o(t), and the engine solves the deconvolution

    z_o(t) = Σ_k Σ_{τ ≤ t} R_{k,o}(t − τ) · ε_k(τ) + u_o(t),     o = 1…q,  t = 0…H−1

    for the shock sequence {ε_k(τ)}, where R_{k,o}(h) is model observable o's impulse response to shock k at horizon h, ε_k(τ) is shock k arriving in quarter τ, and u_o(t) is the residual. Stacking the q·H observation rows into z and the K·H unknowns into ε turns this into z = Θ·ε + u, with Θ the block-Toeplitz response matrix built by buildTheta.

    Symbol Meaning

    D diag(‖Θ·₁‖ … ‖Θ·₍KH₎‖), the column-norm scaling; ΘN = Θ·D⁻¹

    λ 1e-8 · mean(diag(ΘNᵀW²ΘN))
    u residual, u = z − Θ·ε̂

    The estimator is the minimum-norm least-squares solution under the column scaling,

    ε̂ = D⁻¹ · argmin ‖ε̃‖  subject to minimising ‖W(Θ·D⁻¹·ε̃ − z)‖²

    computed numerically, not by an SVD. decompose forms the Gram matrix G = Θ_wᵀΘ_w, adds the ridge λ = 1e-8·mean(diag G), LU-factors (G + λI) once, solves the ridge normal equations, and then runs REFINE_STEPS = 2 iterative-refinement sweeps against that same factorisation. Every iterate stays in range(Θᵀ), so the refined solution converges to the min-norm least-squares solution — the pinv the MATLAB benches use. The module records that the refinement drops the worst-case recovery error from about 7e-7 (bare ridge, inside but at the edge of the 1e-6 licence criterion) to about 1e-15; those two figures are documented at driversDecomp.ts:14–16 and are not independently re-measured here.

    The column-normalised equal-response-energy prior¶

    Before the solve, every column of Θ is divided by its Euclidean norm, and the recovered coefficients are mapped back as ε_j = ε̂N_j / ‖Θ·ⱼ‖ (a column whose norm falls below 1e-12 keeps a scale of 1, so it stays inert rather than being amplified — the MATLAB cn(cn < 1e-12) = 1). This is the "v3 colnorm" solver of pipeline/bench_class_recovery.m, and it imposes an equal-response-energy prior across shocks: the ℓ² penalty no longer prefers whichever shock moves the observables most per unit of ε.

    It matters because a model's shocks differ by an order of magnitude in response energy. Measured from the shipped US_SW07/SW.json, the stacked three-observable H = 12 response norms run from 1.28 for interest_ through 2.12 (fiscal_), 4.21 (eqs), 4.50 (eb), 4.93 (ea) and 11.58 (ew) to 13.84 for epinf. Under a raw min-norm solve the small-response monetary shock is priced out of its own attribution; under column normalisation it is not. In identified configurations the scaling is a pure reparameterisation and the licence fixtures still pass at ≤ 1e-6 (tests v3-1a, v3-1b); in underdetermined ones it removes the small-column bias — class_recovery_results.txt records SW07 at three observables improving from 32% to 5% mean off-class leakage. Its signature is test v3-1c: with two exactly collinear shocks whose response norms differ 2:1, the shipped solver splits the contribution equally where the raw min-norm would split it 4:1.

    Contributions are always formed through the raw, unweighted Θ and the un-normalised ε, because Θ·ε ≡ ΘN·ε̂N exactly. Row weights therefore never touch the reported contributions; they change only which solution the underdetermined solve selects.

    decompose¶

    function decompose(
  irf: ModelIRFs,                       // shock name → { observable field → response path }
  shocks: string[],                     // the K named units, in the model's fixed order
  observables: DecomposeObservable[],   // the q watched rows: { key, irfField, path, weight? }
  H = DRIVERS_H,
): DriversDecomposition

    irf is the model's IRF file as shipped (Record<shock, Record<observableField, number[]>>); index 0 of every response array is the pre-impact zero, so R_{k,o}(h) is read as irf[shock][field][h + 1], mirroring MATLAB's s.obs(2:H+1). The shipped arrays are length 21, so h = 0…19 is available and the engine uses the first twelve. Each DecomposeObservable carries a display key, the irfField to read from the model (usually the same string), the observable's deviation path of at least H entries, and an optional row weight (1 or absent for the three locked observables). The result is

    interface DriversDecomposition {
  shocks: string[]; observableKeys: string[]; H: number
  eps: Float64Array          // K·H, shock-major: eps[k*H + τ]
  contributions: number[][][] // [k][o][t], through the UNWEIGHTED Θ
  fitted: number[][]          // [o][t] = Σ_k contributions[k][o][t]
  residual: number[][]        // [o][t] = z[o][t] − fitted[o][t]
  z: number[][]               // the input paths
  lambda: number; rank: number; rows: number
  regime: 'exact-fit' | 'residual-able'
}

    rows is q·H, rank is thetaRank(Θ) on the unweighted matrix, and regime is 'exact-fit' when rank ≥ rows and 'residual-able' otherwise. The rank threshold is not delicate: the full-rank models on the shipped menu have Θ condition ≲ 1e2 while CA_LS07 sits at about 3e17, some twenty orders of magnitude apart.

    Remark 1 (The budget rule, and the observables that do not raise it). At q watched observables at most q units may be named. decompose throws a message containing the word "budget" when K > q, and the drawer disables every un-named chip once the budget is reached. The rule comes from criterion (e) of bench_simple_decomp.m: SW07 at its native seven observables with its seven usable shocks is fully identified, rank 84/84, noiseless recovery 3.6e-15. Adding an observable raises the budget by one, which is why dy, pinfobs and robs (SW07) and gdp_obs, inflation_obs and Re_obs (CMR14) are excluded from the addable list: each is an invertible linear transform of an observable already watched, so it would raise the budget while buying no new rank, and the identification the rule promises would be fictitious. This is pinned against the data rather than against a curated list — test v3-7 requires each of the four legitimate SW07 addables to buy exactly H = 12 new rank and each of the three excluded transforms to buy exactly zero, alone and together.

    Remark 2 (Collinear units are read jointly, not separately). A pair of shocks whose unit-normalised stacked three-observable H = 12 response paths satisfy |cos| > 0.95 is flagged at build time and shipped in the index; the drawer warns whenever both members are named, quoting the measured |cos|. The split of the contribution within such a pair is not identified — the solver returns the minimum-norm split, which is a convention, not a finding — and naming both members can break same-model recovery outright. useAllShockSelection therefore skips the partner of any shock already picked, and the shipped "Use all" seven for CMR14 recovers far inside the criterion; test v2-2 pins the greedy set at ≤ 1e-6. Hand-picking a collinear pair remains possible under Customize, with the warning. Read a flagged pair as one object.

    Remark 3 (The class view is licensed on three coordinates, not one). classViewLicensed(model, observableKeys, namedShocks) returns true only when the model is US_SW07, the watched observables include all of {output, inflationq, interest, dc, dinve, dw, labobs}, and the named shocks include all of {interest_, eb, fiscal_, eqs, ea, epinf, ew}. bench_class_recovery.m held all three fixed — its passing row is q = 7, K = 7 — and that is the only cell of its five-model, two-solver grid that passes both gates under the shipped colnorm solver, with a perfect diagonal attribution matrix (Monetary/Demand/Supply each 100%, 0% leakage). Un-naming a single class member revokes the licence, because the missing shock's energy is redistributed over the classes that remain, which is exactly what the off-class-leakage criterion measures. The third argument is required rather than optional so that a caller who forgets it gets a compile error. Test v3-3 asserts CLASS_VIEW_OBSERVABLES and CLASS_VIEW_SHOCKS against literal bench coordinates, with a negative case for every one of the seven droppable shocks, so widening either constant turns the test red.

    Remark 4 (Cluster members are chained, not mutually parallel). A cluster is a connected component of the |cos| > 0.95 graph. Collinearity is not transitive, so two members of the same component can sit well below the threshold against each other; they are linked through a chain of collinear neighbours. clusterCompositeIRF therefore returns the genuine first principal component of the member set — 200 power iterations on Σ uuᵀ, seeded from the largest-norm member, unit-normalised, sign fixed by a positive projection on that member — and not a proxy for an already-parallel bundle. Never describe cluster members as pairwise near-parallel.

    Remark 5 (An exact-fit residual is zero by construction). When rank ≥ rows the named units span the observation space and the residual vanishes identically. That is arithmetic, not evidence that the shocks explain the path. The residual becomes a test only in the 'residual-able' regime — which on the shipped menu means a model whose named columns cannot span the q·H rows at all (US_FRB08, with two usable shocks; CA_LS07, left with two once the greedy selection skips its collinear partner), or a configuration in which the user has added observables without naming more shocks.

    Units — the BVAR panel into observable space¶

    The input is the active scenario's level deviation from baseline, [t][j], in smoother level space (100·log for log variables, native units for lin ones). The long-run drift translates baseline and scenario rigidly, so it cancels in the deviation by construction. The three locked observables are measured as follows, and the factors are read off the shipped US_SW07/SW.json, which carries both the MMB common block and SW07's native observables:

    Model observable Built from the BVAR panel as US column
    output GDP level deviation (100·log), identity GDPH

    interest policy-rate deviation, annualised, identity — no division by 4 POLRATE

    The CMR14 conventions were measured from the shipped US_CMR14/SW.json and are regression-pinned in test v2-3: gdp_obs = Δ(output) exactly for every non-trend shock, which anchors the file in percent quarterly log growth; consumption_obs, investment_obs and wage_obs each carry exactly the same 1.0 loading on log_muzstar that the percent-anchored gdp_obs does, which fixes them in the same units (their Δ-term factors, 0.6366, 1.2526 and 0.5647, are internal model-variable scalings and are irrelevant to the data side); wage_obs is the real wage; and hours_obs = 0.01·lhours exactly, the same 0.01 that links output to ly, so it is a percent level deviation.

    Availability is a data question, not a configuration one. The native mode needs the spec columns CH, FNH, LXBC, JGDP and LANAGRA; only the US bloc ships all five. On every other bloc nativeObservablePath returns null, the drawer runs at three observables, the budget is 3, and the class view is unavailable.

    Example 1 (Decompose a US scenario at the licensed configuration)¶

    We decompose the displayed US scenario through the SW07 lens at the one configuration the class view is licensed in: the three locked observables plus the four addable natives, and all seven usable shocks named. We proceed in steps. First we measure the observable rows off the level-deviation panel, then we call the solver. The seven-observable set makes the system square at q·H = 84, so the regime comes back exact-fit and the residual is identically zero.

    import {
  DRIVERS_H, decompose, commonObservablePaths, nativeObservablePath,
  NATIVE_OBS_BY_MODEL, meToWeight, type DecomposeObservable,
} from '@/lib/compute/driversDecomp'

// levelDev: [t][j] scenario-minus-baseline in smoother level space (100·log for log vars)
// specIds:  the bloc's spec variable ids, in column order
const idx = { outputIdx: cGDPH, inflationIdx: cJGDP, rateIdx: cPOLRATE }
const common = commonObservablePaths(levelDev, idx, DRIVERS_H)

const rows: DecomposeObservable[] = [
  { key: 'output',     irfField: 'output',     path: common.output },
  { key: 'inflationq', irfField: 'inflationq', path: common.inflationq },
  { key: 'interest',   irfField: 'interest',   path: common.interest },
]
const map = NATIVE_OBS_BY_MODEL['US_SW07'].map
for (const k of ['dc', 'dinve', 'dw', 'labobs']) {
  const p = nativeObservablePath(k, levelDev, specIds, DRIVERS_H, map)   // null off the US bloc
  if (p) rows.push({ key: k, irfField: k, path: p, weight: meToWeight(1) })
}

const d = decompose(irf, ['interest_', 'eb', 'fiscal_', 'eqs', 'ea', 'epinf', 'ew'], rows, DRIVERS_H)
// d.rows === 84, d.rank === 84  ⇒  d.regime === 'exact-fit', d.residual ≡ 0
// d.contributions[k][o][t] : unit k's contribution to observable o at quarter t
// d.eps[k * DRIVERS_H + τ]  : the recovered shock sequence

    Naming an eighth unit here would throw: the budget is seven (Remark 1).

    Example 2 (Aggregate into classes and check the display identity)¶

    We take the decomposition of Example 1, aggregate its seven shocks into the Monetary, Demand and Supply classes of the shipped class map, and transform the class paths into the units the Output panel draws. The check at the end is the additivity invariant the drawer's chart depends on.

    import {

} from '@/lib/compute/driversDecomp'

    Example 3 (Decompose an FRB/US path through collinearity clusters)¶

    The two 54-shock FRB/US lenses are not separable shock by shock in the three common observables, so the drawer decomposes their empirical collinearity clusters instead.     The Drivers index (DriversIndex / DriversModelMeta)¶

    loadDriversIndex fetches the menu the Drivers drawer is built from — one file, 36 KB, produced by app/scripts/build_drivers_index.mjs (below).     • shocks — the usable shocks: all three common observables present and stacked H = 12 norm ≥ 1e-9.
    • dropped — { shock, reason } for anything excluded; the reasons in use are zero-response and missing-observable. The drawer names them in the lens row rather than hiding them.
    • hasOutput — whether the model exposes an output observable; a false value disables the menu entry. Every shipped entry is true.
    • collinearPairs — { a, b, cos }, cos rounded to six decimals.

    What is fetched when. The index once per session, on the first drawer open; the chosen model's IRF file on model selection, cached per model for the session. The default lens therefore costs 36 KB plus a 215 KB IRF file; selecting either 54-shock FRB/US lens costs a further ~10.7 MB, which is why the drawer records a per-model fetch failure and offers an explicit Retry rather than looping.

    useGvarForecast.ts — drag-aware two-tier GVAR solve hook¶

    Responsibility. The React hook that turns the active bloc's own-pins into a propagated GVAR forecast, keeping the heavy solve off the live drag path. It owns a module Worker (main-thread fallback), a stale-response reqId guard, and two timers (a live debounce + a separate drag-release macrotask). The load-bearing perf fact (verified in the code, useGvarForecast.ts:279): on the then-live US-endogenous panel (measured before the Oct 2026 re-estimation) every mean solve — direct OR full — is ~4571 ms warm / ~13327 ms cold (the US-pinned structure misses the shipped empty-pinStructure coupling artifact and falls to the Neumann fixed point (dim 2180 in the deployed pack) + one Kalman smoother per coupled bloc).

    The drag boundary (useGvarForecast.ts:287):

    • While a drag is in progress (isGvarDragging()): ZERO solves fire — neither value-only nor structure-change. The hook marks pendingReleaseSolveRef = true and bails. The dragged bloc's own line still follows the cursor live because ChartGrid's effective falls back to the single-country condForecast (a ~1–5 ms DK smoother) while gvarFc is frozen at the last solve.
    • On pointer-up (onGvarDragEnd): exactly one direct solve is dispatched, deferred to a ~100 ms macrotask (coalesces back-to-back gestures + lands after the final store write flushes into dataRef). direct is used so the ~95 MB coupling artifact is stripped (withoutCoupling) from the worker post — solveGVARDirect rebuilds/caches M from the per-bloc kernel cache and never consumes the inverse.
    • Non-drag edits (numeric/programmatic pin entry, Reset, scenario switch) dispatch live: full solves immediately (explicit user action — solveFullToken bumped via Compute / "Solve full GVAR"), direct previews after a 120 ms debounce.

    So the full cross-country fixed point (mode:'full', hydrated (I−M)⁻¹) fires only on the explicit Compute / "Solve full GVAR" token bump; everything else is the direct one-hop preview. Pinned by gvar-drag-scheduling.test.ts.

A HeadlineBar is { name, color, values: number[] }, one stacked series in display units — a shock, a class or family total, or a cluster composite. zDisp is the input deviation in the same display units; baselineRows and histRows are the panel's own baseline and history rows (driversInput.baselineDisplay / histDisplay), and lastHist is the bloc's last historical quarter label, from which the quarter axis is generated. buildMainStyleHeadline stacks positive contributions upward and negative ones downward from the baseline, per quarter and independently, and returns null when the baseline display series is shorter than H. buildDeltaHeadline stacks the same bars from zero.

    Remark 6 (The measurement-error slider does nothing at budget-max). At K = q the stacked system is square, and scaling both Θ and z by a positive diagonal row weighting leaves the solution identical: WΘx = Wz ⟺ Θx = z. The slider is therefore inert in the default US configuration; the drawer disables it there and says so, rather than inviting the user to drag a control with no effect. It becomes real as soon as a shock is un-named, which is what gives the added observables a role.

    Remark 7 (The delta view's units need not match the panel that opened the drawer). The chart view auto-follows the main display — when growthDisplay is vsbaseline the drawer opens in "Deviation from baseline", otherwise in "Forecast" — and a manual choice then sticks. But the delta chart's bars are always the panel's rate deviation, while the main panels' "% vs base" mode has a level sub-mode and defaults to level. Auto-follow can therefore put the drawer's chart in different units from the panel that triggered it. The axis title states the unit; do not describe the delta view as matching the panel without that qualification.

    Remark 8 (The shares strip is a norm share, not a variance decomposition). For the selected observable, each series' share is ‖its contribution path‖₂ divided by the sum of those norms plus the residual's (normShares). Shares always sum to 100 and are never negative, so two contributions that offset each other both show as positive shares. It is a readability aid, not a fevd.

    Behaviours worth knowing¶

    The chart shows one observable at a time while the solve uses all watched observables jointly, and the horizon is always twelve quarters regardless of the app's display horizon. Warnings fire for the residual-able regime (quoting rank and rows), for nearly collinear named shocks (quoting the measured |cos| inside the raw fold), for decomposing a path other than the displayed one, for the experimental raw-shock mode, for rank-deficient named columns (rank < K·H), and for leaving the validated default naming on an FRB/US lens. An index fetch failure is reported as an error; a per-model IRF failure is recorded per model and offers a Retry, and the recorded failure blocks the loader effect until the user asks again.

    The default-naming scan. pickDefaultNamed scans every cluster triple through the shipped colnorm solver over 20 sparse-truth seeds (deterministic mulberry32, seed 20260806) against the 1e-6 licence criterion, then picks deterministically among the passers: maximise total member coverage, then prefer a triple containing the interest_ cluster, then first in shipped cluster order. It falls back to pairs and singletons if no triple passes, which does not occur for the shipped data. For US_FRB22, 123 of 1,771 triples pass and the winner is [hqlfpr, interest_, pcer_l], covering 19 of the 54 shocks with a measured worst recovery error of 2.53e-9. For US_FRB22_var, 122 of 1,330 pass and the winner is [eco_l, interest_, ki_l], covering 12 of 54, at 1.32e-7 — passing, but only an order of magnitude inside the criterion, and not pinned by any test. A full-rank Θ is not evidence that a triple is usable: most triples are badly conditioned while still passing the rank test, which is why the drawer warns as soon as the user leaves the shipped default.

    cgvar_b single-pass Bayesian GVAR (MAXIT=1, COVID-as-missing) isolates EM completion
    dfm Bayesian dynamic factor model non-GVAR global benchmark

    Nesting map (stated in the paper): sbvar ⊂ cgvar_b ⊂ emgvar_*; RW/AR nested in every VAR. Count reconciliation: the table lists 8 registry codes, but the rw code emits both rw and its sample-mean climatology sibling clim as separately scored labels, so the scored suite is 9 models (2 proposed + 6 benchmarks + the climatology sibling; arp is a single label).

    Design (final). Recursive expanding window, origins 2010Q1–2024Q4 (drop the 2020 COVID origins from the headline); rolling as-of-t0 trade weights (leak-free — built from IMTS bilateral trade with endPeriod ≤ year(t0); the shipped 2021–2023 weights_full.json is forbidden in the OOS sweep, as it would inject future trade structure); targets {real GDP growth, inflation, short rate} for US/EA/JP/UK/CA/CN; horizons h ∈ {1, 2, 4, 8} (each scored only where a ≤2025Q4 realization exists). COVID-as-missing reapplies in-sample at every origin where 2020Q2–Q4 ≤ t0.

    Scoring. CRPS is the primary density score (ensemble estimator, robust at the modest draw counts); a parametric Gaussian/skew-t log-score corroborates; PIT / coverage for calibration. Significance: Giacomini–White is the headline test (valid under nesting and the recursive scheme), Clark–West for nested point/MSE comparisons, Diebold–Mariano (HAC, HLN-corrected) for non-nested pairs only; multiplicity handled with Romano–Wolf + the Model Confidence Set per (variable, horizon).

    Part 2 — spillovers. Tier A (ships now, zero new estimator code): the conditional-scenario endogenous-vs-frozen US contrast, driven through the shipped gvarSolve.ts (x = Mx + d) — its driver is em-bayesian-gvar-eval/eval/tier_a_scenario.mjs, specified to be exercised from the main repo via a vitest harness (app/src/__tests__/eval/tierA_spillover.test.ts, planned). Tier B (new gvar_girf module, constructible from the exported betahat/Σ + coupling M): GIRF / generalized FEVD / Diebold–Yilmaz index. The protocol is explicit that gvarSolve.ts computes conditional-mean scenario deltas, not GIRFs/FEVD — the only spillover strings in this repo are UI labels.

    Headline result (first full pass — results/tables.{txt,json}, 56 origins, 9 models). AR(p)/DFM have the lowest point CRPS, but the 90% Model Confidence Set is the publishable signal: emgvar_endo is in the inflation MCS at all horizons and the short-rate MCS at h=1,2,4 (indistinguishable from the best on the nominal block), out of the growth MCS at h=1 & h=8; emgvar_endo ⪰ emgvar_frozen across the MCS; and the EM-Bayesian treatment decisively beats the textbook OLS classical GVAR (cgvar_a is removed from most sets). The unconditional point leader for inflation h=1 is the univariate AR(p) (relRMSE 0.641); emgvar_endo (relRMSE 0.799) is the best among the EM/GVAR family, not the overall best. Honest caveats: the draw-based densities are over-confident (PIT cov90 ~0.73–0.83 vs 0.90), and the parametric log-score column is numerically broken (CRPS + MCS are the robust primaries). Tier-A (results/tierA/us_rate_100bp.json) shows non-trivial endogenous-only cross-country feedback the frozen anchor omits, but the magnitudes are large/sign-flipping and it is a multi-period conditional projection, NOT a causal IRF — needs a validation pass before being headlined. The design is final; see em-bayesian-gvar-eval/docs/EMPIRICAL_PROTOCOL.md.

    Known issues & limitations (flagged-for-fix, NOT yet fixed)¶

    Documented honestly so a reader does not mistake a known bias for a verified result. Each is flagged-but-unfixed at the current deployment; cite this section, do not silently rely on the affected output.

    1. CN fiscal debt — inflation double-count (fiscalAccounting.ts). RESOLVED (2026-06). The CN debt-snowball roll-forward computes nominal growth as gQ = Δ(level[idx.gdp]) + Δ(level[idx.deflator]). CN previously shipped a nominal GDP_CN, so the price term was double-counted and the CN debt-to-GDP path was biased. The surgical CN-only re-estimate replaced GDP_CN with real GDP (spec.json var 0 = "CN Real GDP …"), so the snowball now reads the correct real-GDP + price nominal growth, as for the other economies. At the time the fix re-estimated CN only.

    2. [OBSOLETE — longRunTilt.ts removed; superseded by the driftSetter.ts anchor (see above).] The former entropic tilt did not filter non-finite moments before its Newton dual, so an unstable draw's non-finite long-run moment NaN-poisoned the softmax weights and silently emptied the anchor band. The driftSetter.ts display translation does no per-draw reweighting and is not subject to this failure mode.

    3. Only a console-level ρ(M) < 1 divergence guard on the live closed-form solve (gvarSolve.ts, runGvarSolve.ts). The endogenous Neumann fixed point x ← d + M·x iterates to maxIt = 2000 or a relative tolerance 1e-10·(1+‖x‖). If it does not converge, solveGVARClosedFormEndo now computes ρ(M), and runGvarSolve treats ρ ≥ 1 (or a non-finite residual) as diverged: a console warning and no caching. But nothing tells the user on screen, so a refit with ρ ≥ 1 would still show a wrong path. ρ is computed at export time and shipped in the artifact (0.971875 in the deployed pack); check it when the coupling is rebuilt. Fix: surface the diverged flag in the UI (or refuse a coupling with rhoSpectral ≥ 1 at load).

    4. Conditional band uses the FILTERED, not DK-smoothed, covariance (kalman.ts). conditionalForecast returns the smoothed MEAN but extracts the per-horizon variance from the filtered state covariance: variances.push(submatrix(filteredP[t], 0, 0, n, n)) (kalman.ts:405–:409, the comment says "Extract forecast variances from filtered covariances"). The DK smoother would tighten the covariance for quarters that precede a future pin (a later observation reduces earlier-quarter uncertainty); using the filtered covariance does not apply that reduction, so the conditional band is overstated for the quarters before a future pin. The mean is correct; only the band is conservative.

    5. Positional meta indices — STALE-POSITIONAL-INDEX (mitigated, not removed). fiscal_meta.json's six idx values and external_meta.json's five are positional column offsets. Any variable-order change silently re-points them — EA's effRate once landed on the equity index (~col 537) and debt/GDP exploded; in the Oct 2026 data the inserted DEFL_<CC> sent 35 blocs' external fx index to the wrong series (no numerical effect: the FX channel is off). Mitigation: pipeline/port_gvar_exports.py now regenerates both files by variable id on every port; for blocs copied raw, run node pipeline/fix_fiscal_meta_indices.mjs and node pipeline/fix_external_meta_indices.mjs (by id, idempotent; the external one uses the recorded idxIds). fiscal-meta-indices.test.ts and data/meta-column-indices.test.ts guard them — but the deploy workflows do not run tests, so run them before pushing. See DATA_SCHEMA §9 and ARCHITECTURE §7.

    6. The Drivers caveat claims a build-time check that US_FRB08 does not have (DriversDrawer.tsx). For any model outside the eight bench_simple_decomp.m ran, the drawer's bottom caveat says the lens is backed by "a build-time check that the shipped default naming recovers a known shock sequence to 1e-6". That scan (pickDefaultNamed in build_drivers_index.mjs) runs only for clustered models, so it exists for US_FRB22 and US_FRB22_var and not for US_FRB08, which is on the visible menu, has no bench row and carries no defaultNamed. The sentence overstates what backs that one lens. Nothing else is affected — the engine, the budget rule and the collinearity flag are model-independent, and US_FRB08's two shocks at three observables put it in the residual-able regime in any case. Fix: branch the fallback sentence on meta.defaultNamed != null, and for the remaining case say plainly that the lens is unvalidated.

    Build & test¶

    From app/:

    npx tsc --noEmit     # type check
npm test             # FAST suite (vitest run minus the heavy solver --exclude globs)
npm run test:heavy   # HEAVY solver/perf canaries (1 fork) — BOTH halves are the maintainer's gate
npm run build        # static export; prebuild = gzip draws + vintages + pack-verify --full
npm run pack:verify -- --full   # the data-pack check on its own

    Compute-engine tests live in app/src/__tests__/compute/ (data checks in app/src/__tests__/data/). The suite is split — npm test is vitest run minus ten heavy --exclude patterns; npm run test:heavy runs exactly those serialised to one fork; npm run test:all sweeps everything (see BUILD_AND_CI.md). The key canaries (all in the fast suite) are scenario-scale-convention, gvar-convergence (Gauss-Seidel ≡ closed-form), gvar-coupling-artifact (the shipped .gz matches a live build at the current modelSig), fiscal-meta-indices and data/meta-column-indices (the STALE-POSITIONAL-INDEX guards above). The deploy workflows run the build (and so pack-verify --full) but not the tests: running the tests is a manual step before a push.

    The 26 Drivers licence tests — drivers-decomp.test.ts (4), drivers-decomp-v2.test.ts (7) and drivers-decomp-v3.test.ts (15) — are also in the fast suite. They read the shipped IRF files and the shipped index directly, so they fail on a stale app/public/data/dsge/census/ copy as well as on a code regression; see driversDecomp.ts.
